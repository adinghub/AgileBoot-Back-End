# 报告协同 / 药品导入 / 计划复制 / 任务行为分析与批量操作设计

## 1. 背景

本轮补齐三组 App 二期增强能力：

1. 报告分享 / 协同查看
2. 药品导入、常用计划复制
3. 首页 / 任务中心更细的行为分析和批量操作

本次设计遵循两个原则：

1. 优先复用现有一期与二期已完成的家庭共享、用药计划、任务中心能力，避免重复造表。
2. 先把后端接口、权限口径、App 对接路径打通，再按需要继续细化视觉体验。

## 2. 总体设计结论

### 2.1 报告协同

报告协同不单独新增“报告分享表”，而是直接复用已有家庭成员共享体系：

1. 报告天然归属于 `memberId`
2. 当前家庭共享已经支持 `OWNER / EDITOR / VIEWER`
3. 只要当前账号对该成员有可见权限，就应当能查看该成员名下报告
4. 只要当前账号对该成员有编辑权限，就应当能维护报告指标、触发占位 OCR / AI 总结等编辑类动作

因此本期只补两层能力：

1. 报告 DTO 显式返回访问来源和访问角色，方便 App 正确展示“主账号查看 / 协同查看 / 只读查看”
2. 在报告模块下补充“协同账号 / 邀请”便捷接口，内部仍委托家庭共享服务执行

### 2.2 药品导入

药品导入采用“个人药品批量导入”方案，不新增表结构：

1. App 支持粘贴多行文本批量导入
2. 每行支持最简“只填药名”，也支持通过分隔符补充通用名、规格、剂型、类型、用法说明、备注
3. 同一用户自己的药品库内若药名重复，则跳过该行并在返回结果中给出提示

### 2.3 常用计划复制

常用计划复制采用“从已有计划复制生成一条新计划”的方案，不新增表结构：

1. 复制时保留原有药品、频率、提醒时间、剂量等核心规则
2. 允许前端覆盖目标成员、起止日期、状态、备注
3. 复制成功后立即重建未来提醒，保证今日提醒页可马上看到新计划产物
4. 如果跨成员复制时原药品对目标成员所属主账号不可见，则自动降级为“自定义药名”

### 2.4 任务行为分析与批量操作

任务行为分析和批量操作继续依赖现有：

1. `health_follow_up_task`
2. `health_follow_up_task_log`

本次不新增表，改为增强现有任务流：

1. `READ` 行为写入任务日志，形成更完整的行为轨迹
2. 新增任务行为分析接口，输出总览、按任务类型统计、近几日行为趋势
3. 新增批量已读、批量忽略、批量恢复、批量完成接口
4. 首页看板补一张“任务行为分析”预览卡片，任务中心补多选批量操作入口

## 3. 数据与权限设计

## 3.1 报告权限口径

报告权限完全继承家庭成员权限：

1. `OWNER`：可查看、可编辑、可管理协同
2. `EDITOR`：可查看、可编辑、不可管理协同
3. `VIEWER`：可查看、不可编辑、不可管理协同

报告返回对象新增字段：

1. `accessSource`
2. `accessSourceName`
3. `accessRole`
4. `accessRoleName`
5. `isOwner`
6. `canEdit`
7. `canShare`

其中：

1. `canShare = isOwner`
2. App 端据此决定是否展示“管理协同”入口

## 3.2 药品导入文本格式

App 批量导入输入框采用多行文本：

1. 每行一条药品
2. 支持空行自动忽略
3. 支持 `#` 开头作为备注行自动忽略

推荐格式：

```text
阿司匹林
二甲双胍|盐酸二甲双胍|0.5g*20片|片剂|RX|每日两次，餐后服用|糖代谢管理
氯雷他定|氯雷他定|10mg*6片|片剂|OTC|过敏发作时按说明服用
```

字段顺序约定：

```text
药品名称|通用名|规格|剂型|药品类型|用法说明|备注
```

最少只需要第 1 列药品名称。

## 3.3 批量操作口径

批量操作以任务中心列表中的 `taskId` 为主键，不再要求前端自己拆 `taskType + sourceId`。

这样做有两个好处：

1. 任务中心天然已经拿到了 `taskId`
2. 任务中心批量操作不需要再关心底层来源对象是哪种业务类型

服务端仍会在内部回落到原有单条动作逻辑，保证行为一致性。

## 4. 后端接口设计

## 4.1 报告协同接口

### 4.1.1 报告详情 / 列表增强

现有接口增强返回字段：

1. `GET /app/reports`
2. `GET /app/reports/{reportId}`

新增返回：

```json
{
  "accessSource": "OWNER",
  "accessSourceName": "主账号",
  "accessRole": "EDITOR",
  "accessRoleName": "协同编辑",
  "isOwner": false,
  "canEdit": true,
  "canShare": false
}
```

### 4.1.2 报告协同账号与邀请

新增：

1. `GET /app/reports/{reportId}/collaborators`
2. `GET /app/reports/{reportId}/share-invites`
3. `POST /app/reports/{reportId}/share-invites`
4. `DELETE /app/reports/{reportId}/share-invites/{inviteId}`
5. `DELETE /app/reports/{reportId}/collaborators/{shareId}`

实现方式：

1. 先根据 `reportId` 查出 `memberId`
2. 再复用 `FamilyMemberApplicationService` 中已有的协同与邀请逻辑

## 4.2 药品导入接口

新增：

1. `POST /app/drugs/import`

请求体：

```json
{
  "rawText": "阿司匹林\n二甲双胍|盐酸二甲双胍|0.5g*20片|片剂|RX|每日两次，餐后服用|糖代谢管理",
  "defaultDrugType": "OTC",
  "defaultStatus": 1
}
```

返回：

```json
{
  "requestedCount": 2,
  "importedCount": 2,
  "skippedCount": 0,
  "duplicateCount": 0,
  "importedDrugs": [],
  "skippedDrugNames": []
}
```

说明：

1. 重复药名不抛全局异常，按跳过处理
2. 返回结果中明确告知导入成功数、跳过数、重复数

## 4.3 用药计划复制接口

新增：

1. `POST /app/medication/plans/{planId}/copy`

请求体：

```json
{
  "targetMemberId": 1001,
  "startDate": "2026-04-23",
  "endDate": "2026-04-30",
  "status": 1,
  "remark": "复制为本周常用计划"
}
```

返回：

```json
{
  "planId": 2002,
  "memberId": 1001
}
```

说明：

1. 若请求体字段为空，则默认沿用原计划对应字段
2. 复制成功后立即重建未来提醒

## 4.4 任务行为分析接口

新增：

1. `GET /app/follow-up/tasks/analytics`

返回结构包含：

1. 任务总量总览
2. 未读 / 待跟进 / 已延后 / 已完成 / 已忽略统计
3. 已读率、完成率
4. 各任务类型分布
5. 最近 7 天行为趋势

## 4.5 任务批量操作接口

新增：

1. `POST /app/follow-up/tasks/batch-read`
2. `POST /app/follow-up/tasks/batch-ignore`
3. `POST /app/follow-up/tasks/batch-restore`
4. `POST /app/follow-up/tasks/batch-complete`

通用请求体：

```json
{
  "taskIds": [1, 2, 3],
  "remark": "批量处理"
}
```

通用返回：

```json
{
  "requestedCount": 3,
  "successCount": 2,
  "skippedCount": 1,
  "successTaskIds": [1, 2],
  "skippedItems": [
    {
      "taskId": 3,
      "reason": "当前任务类型不支持完成操作"
    }
  ]
}
```

说明：

1. 批量接口采用“部分成功”策略
2. 单条失败不会回滚整个批次
3. 前端根据返回结果提示用户哪些任务被跳过

## 5.3 用药计划

6. 批量完成

## 6. 后台管理前端影响

本轮需求主体为 App 端增强，不新增后台管理页。

原因：

1. 报告协同能力复用的是现有家庭共享后台能力
2. 药品导入是 App 用户自己的个人药品导入，不是后台系统药品批量导入
3. 任务行为分析和批量操作属于用户态任务中心行为，不属于后台运营配置页

因此本轮后台管理前端无需新增页面，但相关设计文档与后端接口会保持可扩展，后续若需要后台审计看板，可直接复用任务日志分析结果。

## 7. 数据库影响

本轮默认不新增表结构。

说明：

1. 报告协同复用家庭共享表
2. 药品导入复用现有药品表
3. 计划复制复用现有计划表和提醒表
4. 行为分析复用任务表和任务日志表
5. `READ` 行为直接写入现有任务日志表的 `action_type`

## 8. 联调顺序建议

1. 后端先补 DTO、命令对象、服务实现和控制器接口
2. App 同步对接报告协同、药品导入、计划复制
3. App 再补首页任务分析卡片和任务中心批量操作
4. 最后执行编译与静态检查，确保三端联调可用
