# 会员体系设计

## 1. 设计目标

健康系统会员体系需要同时满足三类业务诉求：

1. 支撑 App 端会员购买、兑换、到期、续期和权益查询。
2. 支撑后台对会员等级、会员权益、兑换码和用户会员关系做统一运营管理。
3. 为后续“AI 解析改成用户主动调用”提供稳定的权益判断和次数消耗基础设施。

本次设计参考 `E:\code\AssetFlow` 项目已经落地的会员拆层方案，但结合健康系统当前业务规模，先落一套能直接服务：

- AI 报告解析
- AI 结果解读
- AI 总结
- 家庭成员数量上限
- 报告上传数量上限
- 用药计划数量上限

的 MVP 会员体系。

## 2. 分层结构

会员体系按 7 层拆分：

1. 会员权益定义 `member_feature`
2. 会员等级 `member_level`
3. 会员等级权益矩阵 `member_level_feature`
4. 用户会员关系 `user_member`
5. 会员兑换码 `member_redeem_code`
6. 会员权益次数使用记录 `member_feature_quota_usage`
7. 用户会员订单 / 订阅 `user_member_order`、`user_member_subscription`

这样拆分的原因是：

1. 权益和等级分离后，后续新增会员能力不需要改用户关系表。
2. 等级矩阵独立后，产品调价、改次数、改默认规则时只需要改后台配置。
3. 用户会员关系与订阅合同分离后，支持兑换码赠送、后台赠送、手工补偿、订阅续费等不同来源。
4. 次数消耗独立落表后，AI 能力可以稳定按天 / 按月限额。

## 3. 关键表说明

### 3.1 `member_feature`

表示“系统里有哪些会员能力”。

核心字段：

- `feature_code`：权益编码，全局唯一
- `feature_name`：权益名称
- `feature_type`：权益类型，`SWITCH / LIMIT / QUOTA`
- `quota_period_type`：次数周期，`DAY / MONTH`
- `free_enabled`：免费默认是否可用
- `free_limit_value`：免费默认额度，`null` 表示不限
- `is_builtin`：是否内置权益

推荐首批内置权益：

- `AI_REPORT_PARSE`
- `AI_REPORT_PARSE_QUOTA`
- `AI_RESULT_INTERPRETATION`
- `AI_RESULT_INTERPRETATION_QUOTA`
- `AI_REPORT_SUMMARY`
- `AI_REPORT_SUMMARY_QUOTA`
- `MAX_FAMILY_MEMBER`
- `MAX_REPORT_UPLOAD_COUNT`
- `MAX_ACTIVE_MEDICATION_PLAN`

### 3.2 `member_level`

表示套餐本身。

核心字段：

- `level_code`
- `level_name`
- `price`
- `duration_days`
- `benefit_desc`

推荐首期等级：

- `FREE`
- `PLUS`
- `PRO`

说明：

1. `FREE` 更多是一种默认语义，不一定需要为每个用户都显式创建 `user_member` 记录。
2. `duration_days = null` 表示长期有效或由外部来源决定有效期。

### 3.3 `member_level_feature`

表示“某个会员等级对某项权益的最终覆盖值”。

核心字段：

- `member_level_id`
- `member_feature_id`
- `enabled`
- `limit_value`

覆盖规则：

1. 如果某等级未显式配置某权益，则回退到 `member_feature` 的免费默认配置。
2. 如果显式配置，则优先使用等级覆盖值。

### 3.4 `user_member`

表示用户当前的会员关系。

核心字段：

- `user_id`
- `member_level_id`
- `effective_start_time`
- `effective_end_time`
- `status`
- `source_type`
- `source_id`

`source_type` 建议值：

- `SUBSCRIPTION`
- `REDEEM_CODE`
- `ADMIN_GRANT`

### 3.5 `member_redeem_code`

表示后台批量生成并发放给用户的兑换码。

核心字段：

- `batch_no`
- `redeem_code`
- `member_level_id`
- `level_code_snapshot`
- `level_name_snapshot`
- `price_snapshot`
- `duration_days_snapshot`
- `code_status`
- `redeemed_user_id`
- `redeemed_time`
- `expire_time`

兑换规则：

1. 每个兑换码只能使用一次。
2. 已过期 / 已禁用 / 已兑换的兑换码不可再次使用。
3. 如果用户当前已有同等级有效会员，兑换后顺延有效期。
4. 如果用户当前已有其他等级的有效会员，首期直接拒绝跨等级叠加。

### 3.6 `member_feature_quota_usage`

表示按周期统计的权益次数消耗。

核心字段：

- `user_id`
- `member_feature_id`
- `feature_code_snapshot`
- `quota_period_type`
- `period_key`
- `used_count`

说明：

1. `DAY` 场景下 `period_key` 形如 `20260427`
2. `MONTH` 场景下 `period_key` 形如 `202604`
3. 该表是 AI 主动调用限次的核心支撑表

### 3.7 `user_member_order`

表示会员订单流水。

核心字段：

- `order_no`
- `user_id`
- `member_level_id`
- `order_type`
- `order_status`
- `source_type`
- `order_amount`
- `effective_start_time`
- `effective_end_time`

首期即使未接真实支付，也建议保留该表：

1. 后台赠送可记订单
2. 兑换码兑换可记订单
3. 后续接支付时无需推翻结构

### 3.8 `user_member_subscription`

表示订阅合同。

核心字段：

- `subscription_no`
- `user_id`
- `member_level_id`
- `subscription_status`
- `auto_renew`
- `current_period_start_time`
- `current_period_end_time`
- `next_renew_time`
- `cancel_time`
- `cancel_reason`

首期可先以“骨架表 + 骨架接口”的方式落地，先不接第三方支付。

## 4. 权益类型说明

### 4.1 `SWITCH`

纯开关型能力。

示例：

- 是否允许 AI 报告解析
- 是否允许 AI 结果解读
- 是否允许 AI 报告总结

### 4.2 `LIMIT`

上限型能力。

示例：

- 最多家庭成员数
- 最多报告上传数
- 最多启用中的用药计划数

### 4.3 `QUOTA`

周期次数型能力。

示例：

- 每月 AI 报告解析次数
- 每月 AI 结果解读次数
- 每月 AI 报告总结次数

## 5. 运行时权益快照

后端需要向 App 提供“当前权益快照”，而不是让 App 自己推导会员规则。

快照接口返回：

1. 当前会员等级
2. 有效期
3. 自动续费状态
4. 当前权益列表

每项权益至少包含：

- `featureCode`
- `featureName`
- `featureType`
- `entitlementSource`
- `enabled`
- `limitValue`
- `usedCount`
- `remainingCount`
- `periodKey`
- `message`

这样做的目的：

1. App 只消费结果，不自己推规则。
2. 后续会员规则变更时，App 无需发版。
3. AI 解析按钮、会员中心、额度提示都可以统一由后端驱动。

## 6. 与 AI 主动调用的关系

后续把 AI 解析改成“用户主动调用”时，统一按以下顺序执行：

1. 查询当前权益快照
2. 校验开关权益是否开启
3. 校验周期次数是否充足
4. 校验用户是否存在被更高优先级规则拦截的业务条件
5. 成功受理后写入 `member_feature_quota_usage`
6. 发起 AI 任务

推荐首期默认规则：

### FREE

- `AI_REPORT_PARSE = 1`
- `AI_REPORT_PARSE_QUOTA = 3 / MONTH`
- `AI_RESULT_INTERPRETATION = 1`
- `AI_RESULT_INTERPRETATION_QUOTA = 3 / MONTH`
- `AI_REPORT_SUMMARY = 0`

### PLUS

- `AI_REPORT_PARSE = 1`
- `AI_REPORT_PARSE_QUOTA = 30 / MONTH`
- `AI_RESULT_INTERPRETATION = 1`
- `AI_RESULT_INTERPRETATION_QUOTA = 30 / MONTH`
- `AI_REPORT_SUMMARY = 1`
- `AI_REPORT_SUMMARY_QUOTA = 20 / MONTH`

### PRO

- 上述能力全部开启
- 次数更高，或部分权益不限额

## 7. 后台模块建议

后台建议首期提供 5 个页面：

1. 会员权益定义
2. 会员等级管理
3. 会员等级权益配置
4. 用户会员管理
5. 会员兑换码管理

订阅详情建议从“用户会员管理”进入查看，不单独做一级菜单。

## 8. App 模块建议

App 首期新增“会员中心”即可，入口建议放在“我的”页。

建议包含：

1. 当前会员卡片
2. 当前权益快照
3. 可开通等级列表
4. 兑换码入口
5. 最近订单

报告页与 AI 入口统一只读后端权益快照，不直接依赖会员等级名称。

## 9. 首期 MVP 实施范围

首期优先落地：

1. 会员权益定义
2. 会员等级
3. 等级权益矩阵
4. 用户会员关系
5. 会员兑换码
6. 权益次数使用记录
7. 当前权益快照接口
8. 后台 5 个管理接口
9. App 会员中心基础接口

订阅支付链路：

1. 表结构和接口先落骨架
2. 支付网关、自动续费调度后续迭代接入
