# 慢病专项复查任务与首页卡片设计

## 1. 背景

慢病专项通用档案已经支持按 `diseaseCode` 配置所有慢病，不再只围绕单个病种实现。专项详情页可以基于体检报告、健康问题和用药计划聚合趋势，但用户仍缺少两个高频入口：

1. 在某个慢病专项下快速创建下一次复查提醒。
2. 在首页快速看到当前是否已有慢病专项、是否有高优先专项、是否有复查任务。

本次设计在不新增慢病任务表的前提下，复用已有首页 `operation_task` 待跟进任务流，保证慢病复查提醒能进入首页任务、任务中心和统一跳转协议。

## 2. 目标

1. App 可以在慢病专项列表和专项看板中一键创建复查任务。
2. 复查任务按慢病档案 `profileId` 去重，同一个档案只保留一条当前有效的复查任务。
3. 首页看板增加慢病专项摘要卡，展示专项数量、高优先专项数量、复查任务数量和推荐进入的专项。
4. 首页待跟进任务点击慢病复查任务时，统一跳转到工作台慢病专项标签。
5. 继续保持慢病专项的通用能力，所有逻辑只依赖 `profileId` 和 `diseaseCode`，不写高血压、糖尿病等病种分支。

## 3. 后端设计

### 3.1 复查任务复用 operation_task

新增接口：

```http
POST /app/chronic-diseases/{profileId}/review-task
```

请求体可为空：

```json
{
  "reviewDate": "2026-06-01",
  "remark": "可选备注"
}
```

为空时后端默认使用当前日期 30 天后作为复查提醒日期。

复查任务写入 `operation_task`：

| 字段 | 取值 |
| --- | --- |
| `owner_user_id` | 慢病档案归属用户 |
| `member_id` | 慢病档案成员 |
| `target_biz_type` | `CHRONIC_REVIEW` |
| `target_biz_id` | 慢病档案 `profileId` |
| `target_page_code` | `WORKSPACE_CHRONIC_DISEASE` |
| `target_anchor_code` | `CHRONIC_DISEASE_DASHBOARD` |
| `start_time` | 复查日期当天开始 |
| `end_time` | 复查日期后 7 天当天结束 |
| `risk_level` | 慢病档案关注优先级，缺省为 `MEDIUM` |
| `priority_weight` | HIGH=30，MEDIUM=20，LOW=10 |

### 3.2 去重更新策略

后端创建任务时会先查找同一用户、同一 `profileId`、同一 `CHRONIC_REVIEW` 且仍有效的任务。

如果存在，则更新原任务的标题、内容、时间窗口和备注；如果不存在，则新建任务。

这样可以避免用户多次点击后首页出现多条含义相同的慢病复查提醒。

### 3.3 首页慢病摘要

`HealthHomeDashboardDTO` 新增：

```json
{
  "chronicDiseaseSummary": {
    "activeProfileCount": 2,
    "highRiskProfileCount": 1,
    "reviewTaskCount": 1,
    "latestProfileId": 12,
    "latestMemberId": 5,
    "latestMemberName": "张三",
    "latestDiseaseName": "高血压管理",
    "summary": "当前管理2个慢病专项；其中1个需要高优先关注；已有1条复查提醒待执行；建议优先查看张三的高血压管理专项。"
  }
}
```

首页摘要只做轻量统计，不扫描报告指标明细。完整趋势仍由慢病专项详情接口负责，避免首页接口变重。

## 4. App 设计

### 4.1 首页卡片

首页 `HomeDashboardData` 增加 `chronicDiseaseSummary` 模型。首页在快捷统计后展示慢病专项卡片：

1. 有专项时展示推荐成员和推荐病种。
2. 无专项时展示建立专项引导。
3. 卡片展示专项数、高优先数、复查任务数。
4. 点击卡片或右上角动作进入工作台慢病专项。

### 4.2 一键创建复查任务

慢病专项列表卡和专项看板底部都提供“创建复查任务”。

App 调用：

```dart
_repository.createReviewTask(profileId: profile.profileId)
```

不传日期时使用后端默认 30 天。后续如果要加日期选择器，仓储方法已经保留 `reviewDate` 可选参数，不需要再改接口封装。

### 4.3 统一跳转

App 壳层新增：

1. `WorkspaceNavigationTarget.chronicDiseaseList`
2. `WorkspaceNavigationTarget.chronicDiseaseDetail`
3. `openWorkspaceChronicDiseases({int? profileId, int? memberId})`

后端返回 `WORKSPACE_CHRONIC_DISEASE` 时，App 统一切到工作台慢病专项标签。

当前慢病标签页尚未暴露外部 controller，因此 `profileId` 先保留在壳层意图中，当前版本先稳定切到慢病专项标签。后续如果需要自动打开指定档案看板，只需要给 `ChronicDiseaseWorkspaceTab` 增加控制器，不需要再改首页任务协议。

## 5. 不改动边界

1. 不新增慢病复查任务表。
2. 不改变首页待跟进任务的既有任务状态、已读、完成、忽略机制。
3. 不改变慢病专项通用档案结构。
4. 不写任何单病种硬编码逻辑。
5. 不在首页重复计算慢病指标趋势。

## 6. 验证

本次改动需要验证：

1. 后端 `mvn -pl healthtrail-domain,healthtrail-api -am -DskipTests compile` 通过。
2. App `flutter analyze` 通过。
3. App 慢病专项点击“创建复查任务”后，接口返回任务日期并 toast 成功。
4. 首页刷新后慢病专项卡片展示统计数据。
5. 首页慢病复查任务点击后能切到工作台慢病专项标签。
