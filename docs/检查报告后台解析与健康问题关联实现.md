# 检查报告后台解析与健康问题关联实现

## 1. 功能目标

本次补齐检查报告上传后的完整服务端链路：

1. 用户在 App 上传检查报告文件
2. 后端保存文件和报告元信息
3. 后端自动投递后台解析任务
4. 后台解析 PDF / 图片 / 文本报告
5. 解析结果写入报告指标表
6. 指标生成标准指标编码
7. 趋势按标准指标编码聚合
8. 异常指标自动关联健康问题
9. App 端展示趋势和关联健康问题


## 2. 后台解析流程

上传接口仍然是：

```text
POST /app/reports
```

上传成功后，服务端会立即返回，后台线程继续执行解析：

```text
保存文件
  -> 保存 report 主表
  -> parse_status = 待解析
  -> ocr_status = 待处理
  -> 后台线程 parseReportFile
  -> parse_status = 解析中
  -> ocr_status = 处理中
  -> 抽取文本
  -> 抽取指标
  -> 覆盖写入 report_item
  -> 重算 analysis_summary
  -> 同步 health_problem
  -> parse_status = 已解析 / 解析失败
```


## 3. 文件解析能力

### 3.1 PDF

文本型 PDF 使用 PDFBox 直接抽取文本。

如果 PDF 本身是扫描图片，PDFBox 只能读到空文本，此时需要走图片 OCR 或后续接专业 OCR 服务。

### 3.2 图片 / 扫描 PDF

图片 OCR 已抽象为统一接口，当前优先支持阿里云 OCR。

阿里云配置示例：

```yaml
health:
  report:
    ocr:
      enabled: true
      provider: ALIYUN
      aliyun:
        endpoint: ocr-api.cn-hangzhou.aliyuncs.com
        type: Advanced
```

AccessKey 可以使用配置项，也可以使用环境变量：

```text
ALIBABA_CLOUD_ACCESS_KEY_ID
ALIBABA_CLOUD_ACCESS_KEY_SECRET
```

本地命令行 OCR 仍保留为兜底适配器，配置项：

```yaml
health:
  report:
    parser:
      image-ocr-command: "tesseract {file} stdout -l chi_sim+eng"
      command-timeout-seconds: 60
```

说明：

1. 扫描 PDF 如果 PDFBox 抽不到文本，会继续交给统一 OCR 客户端
2. 阿里云实现使用文件流上传，不要求本地报告文件有公网 URL
3. 命令行 OCR 中 `{file}` 会被替换成本地报告文件路径
4. 后续可新增腾讯 OCR、百度 OCR 或自研 OCR 实现，不需要改报告解析主流程

### 3.3 文本文件

`txt`、`html`、`htm`、`csv` 会直接按 UTF-8 读取。


## 4. 指标抽取规则

当前先用轻量规则抽取常见格式：

```text
指标名称  结果值  单位  参考范围
空腹血糖  6.4  mmol/L  3.9-6.1
尿酸      460  umol/L  208-428
白细胞    11.2 10^9/L  3.5-9.5
```

抽取后会复用现有 `HealthReportItemModel`：

1. 校验指标名称和结果值
2. 自动解析参考范围上下限
3. 自动判定正常、偏低、偏高、异常、待判断
4. 保存到 `report_item`


## 5. 标准指标编码

`report_item` 新增字段：

```text
standard_item_code
```

该字段用于把不同报告里的同类指标归并到同一趋势维度。

例如：

```text
空腹血糖 / 葡萄糖 / GLU -> GLU
尿酸 / UA -> UA
总胆固醇 -> TC
甘油三酯 -> TG
白细胞 -> WBC
```

如果没有命中内置规则，会生成 `CUSTOM_` 前缀的兜底编码，避免趋势比较完全失效。


## 6. 趋势对比调整

趋势接口仍然是：

```text
GET /app/reports/{reportId}/trends
```

原逻辑按“同成员 + 同报告类型”找历史报告。

现在改为：

```text
当前报告指标
  -> 提取 standard_item_code
  -> 找同成员下包含相同 standard_item_code 的历史报告
  -> 按 standard_item_code 匹配趋势点
```

这样血糖来自体检报告、门诊化验单或其他检查报告时，仍然可以进入同一条趋势线。


## 7. 健康问题关联

新增表：

1. `health_problem`
2. `health_problem_evidence`

同步规则：

1. 只处理异常指标
2. 同一成员同一 `standard_item_code` 复用同一个健康问题
3. 每条异常指标作为一条问题证据
4. 健康问题不是疾病诊断，只表示风险线索或持续关注主题

新增接口：

```text
GET /app/reports/{reportId}/health-problems
```

App 详情页会展示当前报告关联到的健康问题。

## 9. 注意事项

1. 解析结果是“指标/所见”，不是疾病诊断
2. 图片 OCR 需要部署环境额外配置 OCR 命令
3. 扫描 PDF 如果没有文本层，需要先转图片或接专业 OCR
4. 后台解析生成的指标建议用户确认后再作为严肃健康档案依据
5. 后续可把标准指标编码规则迁移到数据库字典，支持运营维护
