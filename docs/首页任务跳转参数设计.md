# 首页任务跳转参数设计

## 1. 功能目标

当前首页待跟进任务和任务中心已经能返回：

1. 任务基础信息
2. 可操作按钮
3. 时间线

但前端在点击任务后，仍然需要自己根据 `taskType` 推断：

1. 应该跳到提醒页还是报告页
2. 应该带哪个业务ID
3. 报告页默认打开哪个区域

这会让首页、任务中心、详情页三处都重复维护同样的判断逻辑。

因此本期补充统一的跳转参数。


## 2. 设计原则

### 2.1 后端返回页面编码，不直接返回前端真实路由

后端新增统一导航对象 `navigation`，返回：

1. `targetPageCode`
2. `targetPageName`
3. `targetBizId`
4. `targetBizType`
5. `targetTabCode`
6. `targetAnchorCode`
7. `targetAnchorName`

这样后端只表达“应该跳哪类页面”，
而不会把客户端真实页面路径耦合进接口协议。

### 2.2 首页、任务中心、任务详情统一口径

本次统一在以下返回对象中补充 `navigation`：

1. 首页待跟进事项 `followUpItems`
2. 任务中心列表单条任务
3. 任务详情中的 `taskInfo`

这样 App 前端不同页面都可以复用同一套跳转解析逻辑。


## 3. 跳转规则

### 3.1 用药提醒任务

当任务类型为 `REMINDER` 时，返回：

1. `targetPageCode = MEDICATION_REMINDER_DETAIL`
2. `targetBizId = reminderId`
3. `targetBizType = REMINDER`
4. `targetTabCode = PROCESS`
5. `targetAnchorCode = REMINDER_FEEDBACK`

### 3.2 报告建议任务

当任务类型为 `REPORT_ADVICE` 时，返回：

1. `targetPageCode = HEALTH_REPORT_DETAIL`
2. `targetBizId = reportId`
3. `targetBizType = REPORT_ADVICE`
4. `targetTabCode = ADVICE`
5. `targetAnchorCode` 会按首条建议进一步细分

当前支持：

1. `REPORT_ADVICE`：优先落到报告建议区
2. `REPORT_ABNORMAL_ITEMS`：优先落到异常指标区
3. `REPORT_ORIGINAL_FILE`：优先落到原始报告区

这里的 `ADVICE` 只是建议默认落点，
具体前端是否实现成 tab、锚点或模块滚动，由客户端自己决定。


## 4. 为什么还保留 reminderId / reportId

首页待跟进事项 DTO 中原有：

1. `reminderId`
2. `reportId`

本次不删除这些字段，原因是：

1. 兼容现有前端
2. 避免旧版本联调立即受影响
3. 新版本前端可逐步切换到统一 `navigation`


## 5. 后续建议

建议下一步继续补：

1. 任务详情返回“推荐下一步动作”文案
2. 推荐动作增加优先级或风险等级
3. App 推送消息也复用同一套跳转参数结构
