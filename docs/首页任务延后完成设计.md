# 首页任务延后完成设计

## 1. 功能目标

首页待跟进事项已经能聚合任务流，
但如果任务只能展示、不能操作，用户体验仍然不完整。

因此本期继续补充首页任务操作能力，重点支持：

1. 任务延后处理
2. 报告建议任务完成本轮跟进
3. 首页任务忽略
4. 任务已读回写
5. 快捷延后时间选项
6. 任务中心恢复显示


## 2. 设计思路

### 2.1 不直接改原始业务数据

首页任务只是提醒模块和报告模块在首页场景下的一层聚合视图。

因此任务操作不应直接去修改：

1. 用药提醒原始计划时间
2. 报告原始异常结果
3. 运营任务原始投放配置

否则会让首页任务流和原始业务状态混在一起，后续非常难维护。

### 2.2 任务状态与操作日志拆表保存

当前通过以下两张表承接首页任务操作：

1. `health_follow_up_task`：保存任务当前状态
2. `health_follow_up_task_log`：保存每一次任务操作轨迹

例如：

1. 某条提醒任务被延后到下午 18:00 再显示
2. 某份报告建议被标记为本轮已处理
3. 某条任务被标记为已读或忽略

首页渲染和任务中心查询时再把：

1. 原始任务来源
2. 当前任务状态
3. 任务操作日志

做一次合并，得到最终应该展示给用户的任务流。


## 3. 数据模型

### 3.1 表 `health_follow_up_task`

核心字段：

1. `task_id`
2. `owner_user_id`
3. `member_id`
4. `task_type`
5. `source_id`
6. `task_status`
7. `read_status`
8. `read_time`
9. `delayed_until`
10. `complete_time`
11. `action_remark`

### 3.2 表 `health_follow_up_task_log`

核心字段：

1. `task_log_id`
2. `task_id`
3. `action_type`
4. `action_time`
5. `action_remark`
6. `operator_user_id`

### 3.3 任务类型

当前支持：

1. `REMINDER`
2. `REPORT_ADVICE`
3. `OPERATION`

### 3.4 任务状态

当前支持：

1. `0`：待跟进
2. `1`：已延后
3. `2`：已完成
4. `3`：已忽略


## 4. 规则设计

### 4.1 提醒任务

提醒任务支持“延后、已读、忽略、恢复”，
不支持直接通过首页任务流标记完成服药。

原因：

1. 提醒真正完成应该由提醒模块的“已服药 / 已跳过”接口负责
2. 首页任务流只负责调整首页曝光时机和任务展示状态

### 4.2 报告建议任务

报告建议任务支持：

1. 已读
2. 延后
3. 完成本轮跟进
4. 忽略
5. 恢复

因为报告建议本身就是首页加工出的任务对象，
它不需要像提醒那样再去回写原始业务执行状态。

### 4.3 运营任务

运营任务进入首页任务流后，也复用统一任务状态模型。

但运营任务的本质仍然是“引导用户进入某个业务页”，因此：

1. 不在首页任务流里创建新的底层药品、提醒、报告数据
2. 主要依赖统一导航协议打开真实业务页

### 4.4 首页过滤规则

首页在生成任务流时会按照以下规则合并操作状态：

1. 已完成任务直接不再展示
2. 已延后且还没到时间的任务先不展示
3. 已延后但时间已到的任务重新展示
4. 已忽略任务不再展示
5. 已读状态不影响任务是否展示，但会影响前端样式与排序说明

### 4.5 快捷延后选项

为了减少前端重复计算时间，当前提供三种快捷延后选项：

1. `AFTER_30_MINUTES`
2. `TONIGHT`
3. `TOMORROW_MORNING`

如果前端需要精确控制，也仍然可以直接传 `delayedUntil`。


## 5. 接口设计

App 端当前共提供以下接口：

1. `GET /app/follow-up/tasks`
2. `GET /app/follow-up/tasks/{taskId}`
3. `GET /app/follow-up/tasks/{taskId}/logs`
4. `POST /app/follow-up/tasks/read`
5. `POST /app/follow-up/tasks/delay`
6. `POST /app/follow-up/tasks/complete`
7. `POST /app/follow-up/tasks/ignore`
8. `POST /app/follow-up/tasks/restore`

### 5.1 任务中心说明

任务中心当前用于统一承接“首页预览之外的完整任务流”，支持查看当前任务和历史任务。

用户可以在任务中心里看到：

1. 哪个任务当前待处理
2. 哪个任务被延后过
3. 哪个任务被忽略过
4. 哪个任务被标记为已完成
5. 这条任务什么时候被已读、延后、忽略、恢复或完成

同时也支持：

1. 按任务类型筛选
2. 按任务状态筛选
3. 查看任务操作时间线
4. 针对可恢复任务执行“恢复显示”
