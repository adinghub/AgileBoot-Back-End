# 后台用药历史依从率管理设计

## 1. 功能目标

本功能用于给后台管理端提供“全局视角的用药执行复盘能力”，覆盖以下场景：

1. 分页查询历史服药记录
2. 按成员、计划、提醒状态、时间范围过滤记录
3. 查看依从率统计摘要
4. 查看日维度依从率趋势

## 2. 已落地实现

本次能力已经落地到以下文件：

1. `healthtrail-admin/src/main/java/com/healthtrail/admin/controller/health/HealthMedicationHistoryController.java`
2. `E:\code\health\healthtrail-front-end\src\api\health\medicationHistory.ts`
3. `E:\code\health\healthtrail-front-end\src\views\health\medicationHistory\index.vue`

## 3. 设计原则

### 3.1 后台使用全量数据视角

App 端查询会受“当前登录用户可访问成员范围”限制。  
后台管理端则直接对全量提醒记录做查询、统计和趋势分析，以满足：

1. 客服排障
2. 运营复盘
3. 管理端数据核对

### 3.2 列表、统计、趋势使用同一套筛选条件

页面里历史记录、依从率摘要、趋势表统一由同一个刷新入口驱动。

这样可以避免出现：

1. 列表看的是 A 时间段
2. 趋势看的是 B 时间段
3. 统计卡片又是另一组条件

## 4. 接口设计

### 4.1 历史记录分页

- 接口：`GET /health/medication/history`
- 权限：`health:medicationHistory:list`

查询参数：

1. `pageNum`
2. `pageSize`
3. `memberId`
4. `planId`
5. `reminderStatus`
6. `startDate`
7. `endDate`

### 4.2 依从率统计

- 接口：`GET /health/medication/adherence/statistics`
- 权限：`health:medicationHistory:query`

统计口径：

`已服药 / （已服药 + 已跳过 + 已过期）`

说明：

1. 待处理提醒不纳入分母
2. 更适合衡量历史执行质量

### 4.3 依从率趋势

- 接口：`GET /health/medication/adherence/trend`
- 权限：`health:medicationHistory:query`

趋势维度：

1. `reminderDate`
2. 当日总提醒数
3. 已服药数
4. 已跳过数
5. 已过期数
6. 待处理数
7. 当日依从率

## 5. 页面设计

### 5.1 搜索区

搜索区支持以下条件：

1. 成员 ID
2. 计划 ID
3. 提醒状态
4. 执行时间范围

### 5.2 概览区

概览卡片展示：

1. 依从率
2. 总提醒数
3. 已服药
4. 已跳过
5. 已过期
6. 待处理

### 5.3 趋势区

趋势区直接展示按日聚合后的明细表，便于后台快速定位某几天执行质量下降的问题。

### 5.4 历史记录区

历史记录区提供分页表格，字段包含：

1. 提醒 ID
2. 计划 ID
3. 成员姓名
4. 药品名称
5. 计划执行时间
6. 提醒状态
7. 发送状态
8. 反馈时间
9. 跳过原因

## 6. 权限设计

页面使用两组权限：

1. `health:medicationHistory:list`
2. `health:medicationHistory:query`

特别说明：

1. 页面首屏会同时请求列表、统计、趋势三个接口
2. 因此联调时通常需要同时授予 `list + query`

## 7. 校验与异常处理

当前后端已做日期范围校验：

1. 若 `startDate > endDate`，直接返回业务异常
2. 当查询为空时，趋势接口返回空数组而不是报错

## 8. 验收建议

建议按以下步骤验收：

1. 不带筛选条件打开页面，确认列表、概览卡片、趋势数据同时加载
2. 使用时间范围筛选，确认三块区域数据同步变化
3. 使用 `memberId + planId` 交叉筛选，确认统计口径合理
4. 构造无数据时间段，确认趋势区显示空态
