# 首页任务推荐动作设计

## 1. 功能目标

首页任务详情接口目前已经返回：

1. 任务基础信息
2. 可操作按钮
3. 时间线
4. 跳转参数

但用户打开任务详情后，仍然需要自己理解：

1. 现在最该先做什么
2. 这条任务的核心动作是什么
3. 打开原始业务页后应该重点关注哪里

因此本期继续补充“推荐下一步动作”。


## 2. 设计思路

### 2.1 推荐动作单独建模

详情接口新增：

`recommendedAction`

包含：

1. `actionPriority`
2. `riskLevel`
3. `riskLevelName`
4. `riskCssTag`
5. `title`
6. `content`
7. `actionText`
8. `navigation`

这样前端可以直接把它渲染成一张“下一步建议卡片”。

### 2.2 尽量复用现有业务文案

为了避免同一个报告在不同页面出现两套不一致建议，
本次规则如下：

1. 提醒任务使用提醒状态和时间生成推荐动作
2. 报告建议任务优先复用现有 `HealthReportAdviceDTO` 中的摘要和首条建议


## 3. 规则设计

### 3.1 提醒任务

提醒任务详情页重点引导用户：

1. 确认是否已服药
2. 如未执行，可进入提醒页选择跳过

如果提醒时间已到，则标题更强调“优先确认本次提醒结果”。

同时：

1. 已到点提醒：高优先关注
2. 稍后提醒：中优先关注

### 3.2 报告建议任务

报告建议任务详情页重点引导用户：

1. 先看本次最重要的一条建议
2. 再决定是否复查、持续观察或结合现有用药计划继续跟进

当前实现中：

1. 优先取首条建议的 `title`
2. 优先取首条建议的 `content`
3. 优先取首条建议的 `actionText`
4. 优先取首条建议的 `priority` 作为推荐动作优先级
5. 根据首条建议的异常标记映射风险等级
6. 若建议列表为空，再回退到报告摘要

### 3.3 来源已失效场景

如果原始提醒或报告记录已经删除，则仍返回推荐动作，
但推荐内容改为：

1. 仅查看历史任务与操作记录
2. 不再引导用户跳转原始业务页
3. 风险等级降为低优先关注


## 4. 接口影响

本次不新增接口，只扩展：

`GET /app/follow-up/tasks/{taskId}`

新增返回字段：

`recommendedAction`

其中新增子字段：

1. `actionPriority`
2. `riskLevel`
3. `riskLevelName`
4. `riskCssTag`


## 5. 后续建议

建议下一步继续补：

1. 风险等级支持结合更多报告规则动态计算
2. 推送消息也复用推荐动作文案
3. 推荐动作支持多锚点候选列表
