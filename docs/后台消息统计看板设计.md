# 后台消息统计看板设计

## 1. 功能目标

当前后台已经具备：

1. 消息审计列表
2. 消息审计详情
3. 单条人工重发
4. 批量重发

但后台仍然缺少一个“全局视角”的消息运行面板，导致只能逐条查问题，不能快速回答：

1. 当前消息总量有多少
2. 失败消息占比高不高
3. 哪类消息发得最多
4. 最近 7 天消息量和失败量是升还是降

因此本期补充后台消息统计看板接口，为后台页面提供统一的统计数据源。


## 2. 设计原则

### 2.1 统计口径直接复用消息中心表

当前统计全部基于：

`health_app_message`

实时计算，不额外引入统计快照表。

这样可以保证：

1. 统计口径与审计列表一致
2. 无需额外同步任务
3. 业务迭代时不会出现审计表和统计表口径脱节

### 2.2 一次接口返回看板所需核心结构

本期统计接口一次返回：

1. 顶部总览
2. 业务场景分布
3. 发送状态分布
4. 最近趋势
5. 失败原因排行

这样后台页面首次进入时不需要再并行调用多个小接口。

### 2.3 趋势图默认返回最近7天

后台趋势图默认返回最近 7 天数据，
同时允许通过 `trendDays` 调整，最大 30 天。

这样兼顾：

1. 默认加载速度
2. 页面首屏可读性
3. 后续按需扩展时间窗口


## 3. 接口设计

新增后台接口：

`GET /health/messages/statistics`

可选查询参数：

1. `ownerUserId`
2. `businessScene`
3. `beginTime`
4. `endTime`
5. `trendDays`
6. `failureReasonTopLimit`


## 4. 返回结构设计

### 4.1 `overview`

顶部总览当前包含：

1. `totalMessageCount`
2. `unreadMessageCount`
3. `sendSuccessCount`
4. `sendFailedCount`
5. `pendingSendCount`
6. `ownerUserCount`
7. `todayCreatedCount`
8. `todayFailedCount`

### 4.2 `sceneDistributions`

按业务场景统计消息数量，当前典型场景：

1. `MEDICATION_REMINDER`
2. `REPORT_FOLLOW_UP`

### 4.3 `sendStatusDistributions`

按发送状态统计消息数量，当前状态包括：

1. 待发送
2. 发送成功
3. 发送失败

### 4.4 `recentTrends`

按天输出趋势点，当前包含：

1. 当日新增量
2. 当日成功量
3. 当日失败量

### 4.5 `failureReasonDistributions`

失败原因排行仅统计当前处于“发送失败”状态的消息，
按最近一次发送结果说明聚合数量。

当前主要目的是帮助后台快速定位：

1. 是不是设备没注册
2. 是不是发送器异常
3. 是不是某类失败正在集中放大


## 5. 后续建议

建议下一步继续补：
