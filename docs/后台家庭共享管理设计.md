# 后台家庭共享管理设计

## 1. 功能目标

本功能用于给后台管理端提供“家庭共享协同”的运维入口，覆盖以下场景：

1. 按主账号、成员姓名、状态检索系统中的家庭成员
2. 查看某个家庭成员当前的协同账号列表
3. 查看某个家庭成员当前的共享邀请列表
4. 在后台直接移除异常协同账号
5. 在后台直接取消失效或误发的邀请码

## 3. 设计原则

### 3.1 后台以“家庭成员”为中心

后台没有额外拆出一张“共享关系管理主页面”，而是围绕家庭成员做运维视角管理。

原因是：

1. 客服和业务同学排障时，通常先知道“哪位家庭成员出了问题”
2. 家庭成员天然就是用药、报告、共享三条业务链路的统一锚点
3. 后台可直接复用 App 端围绕 `memberId` 已经稳定跑通的协同逻辑

### 3.2 只提供排障必需动作

当前后台不负责创建邀请码，也不负责修改共享角色，只收口这几个高频动作：

1. 查看协同明细
2. 查看邀请明细
3. 移除协同
4. 取消邀请

这样可以避免后台和 App 双端同时维护创建流程，降低业务分叉风险。

## 4. 接口设计

### 4.1 成员分页列表

- 接口：`GET /health/family/members`
- 权限：`health:familyShare:list`

查询参数：

1. `pageNum`
2. `pageSize`
3. `ownerUserId`
4. `memberName`
5. `status`

列表核心字段：

1. `memberId`
2. `memberName`
3. `ownerUserId`
4. `ownerNickname`
5. `ownerMobile`
6. `relationType`
7. `status`
8. `activeCollaboratorCount`
9. `pendingInviteCount`

### 4.2 协同账号列表

- 接口：`GET /health/family/members/{memberId}/collaborators`
- 权限：`health:familyShare:query`

说明：

1. 后台接口会先根据 `memberId` 找到成员主账号
2. 再复用 App 端已经存在的协同查询逻辑，避免复制两套业务代码

### 4.3 共享邀请列表

- 接口：`GET /health/family/members/{memberId}/share-invites`
- 权限：`health:familyShare:query`

### 4.4 移除协同账号

- 接口：`DELETE /health/family/members/{memberId}/collaborators/{shareId}`
- 权限：`health:familyShare:remove`

### 4.5 取消共享邀请

- 接口：`DELETE /health/family/members/{memberId}/share-invites/{inviteId}`
- 权限：`health:familyShare:remove`

## 5. 页面设计

### 5.1 搜索区

后台搜索区提供以下筛选项：

1. 主账号 ID
2. 成员姓名
3. 成员状态

### 5.2 列表区

列表页重点突出后台排障最关心的信息：

1. 成员是谁
2. 属于哪个主账号
3. 当前有多少启用中的协同账号
4. 当前有多少待处理邀请

### 5.3 详情弹窗

详情弹窗拆成两块：

1. 左侧展示协同账号列表
2. 右侧展示共享邀请列表

这样客服在处理“用户为什么看不到成员”“邀请码为什么失效”等问题时，不需要反复切页面。

## 6. 权限设计

后台权限与控制器一一对应：

1. 列表：`health:familyShare:list`
2. 详情：`health:familyShare:query`
3. 删除动作：`health:familyShare:remove`

说明：

1. 删除动作同时覆盖“移除协同账号”和“取消共享邀请”
2. 前端按钮通过 `v-auth` 控制显隐，需保证后端菜单正确下发权限码

## 7. 风险与边界

当前后台能力仍保持这些边界：

1. 不在后台创建新邀请码
2. 不在后台改共享角色
3. 不在后台直接编辑家庭成员资料

原因是：

1. 本期目标是补齐运维与联调能力，不是重做完整家庭成员主数据后台
2. 共享创建和角色变更仍以 App 端业务闭环为准更稳

## 8. 验收建议

建议按以下步骤验收：

1. 打开“家庭共享管理”页面，确认列表能正常分页
2. 以存在协同关系的成员打开详情弹窗，确认能看到协同账号和邀请记录
3. 测试取消待接受邀请码，确认列表和弹窗统计同步刷新
4. 测试移除协同账号，确认共享账号从详情页消失
5. 用无 `health:familyShare:remove` 权限的角色登录，确认删除按钮隐藏
