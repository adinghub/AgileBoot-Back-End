# 慢病专项通用档案设计

## 1. 目标

本次实现的是“通用慢病专项”，不是单独做某一个病种。系统通过 `diseaseCode` 和病种配置驱动展示，后续新增高血压、糖尿病以外的慢病，应优先维护配置，而不是继续增加硬编码分支。

核心目标：

1. App 可以给任意家庭成员建立多个慢病专项档案。
2. 慢病专项支持所有慢病，只要后台配置病种编码、病种名称、重点指标编码或关键词即可。
3. 详情页自动聚合该成员最近报告中的相关指标趋势、相关健康问题数量和启用中的用药计划数量。
4. 首期不做医学诊断结论，只做个人健康管理档案、趋势观察和复查提醒入口的基础能力。

## 2. 数据模型

### 2.1 病种配置表

表名：`health_chronic_disease_type`

该表解决“系统支持哪些慢病专项”的问题。关键字段包括：

- `disease_code`：稳定病种编码，例如 `DIABETES`。
- `disease_name`：展示名称，例如糖尿病管理。
- `disease_category`：病种分类，例如代谢、心血管、肾脏。
- `focus_indicator_codes_json`：重点关注指标编码 JSON，例如 `GLU`、`HBA1C`。
- `focus_indicator_keywords_json`：指标名称关键词 JSON，用于报告指标还没有稳定标准编码时兜底。
- `target_summary`：默认管理目标。
- `follow_up_suggestion`：默认随访建议。

这里同时支持“指标编码”和“关键词”的原因是：当前报告解析来自 AI 和人工录入，标准编码可能还不稳定。如果只依赖标准编码，早期很多报告趋势会匹配不到；如果只依赖关键词，后续标准化程度提高后又不够精确。因此两者并行，编码优先、关键词兜底。

### 2.2 用户专项档案表

表名：`health_chronic_disease_profile`

该表解决“哪个成员正在管理哪个慢病专项”的问题。关键字段包括：

- `owner_user_id`：成员主账号。
- `member_id`：家庭成员。
- `disease_code`：病种编码，关联配置表。
- `disease_name_snapshot`：病种名称快照。
- `profile_status`：专项状态，1 跟进中，2 已稳定，3 已关闭。
- `risk_level`：产品关注优先级，`LOW / MEDIUM / HIGH`，不代表医学诊断等级。
- `diagnosed_date`：确诊或建档日期。
- `target_summary`：个性化管理目标。
- `current_summary`：当前情况摘要。
- `last_review_date`：最近复盘日期。

同一成员同一病种只允许存在一条未删除档案，避免 App 重复展示多个相同专项。

## 3. 后端接口

基础路径：`/app/chronic-diseases`

接口：

1. `GET /app/chronic-diseases/types`
   查询启用中的慢病病种配置。

2. `GET /app/chronic-diseases?memberId=&profileStatus=&keyword=`
   查询当前账号可访问的慢病专项档案。成员权限沿用家庭协同访问控制。

3. `POST /app/chronic-diseases`
   新增慢病专项档案。共享协同账号必须具备编辑权限。

4. `GET /app/chronic-diseases/{profileId}`
   查询慢病专项详情看板。

5. `PUT /app/chronic-diseases/{profileId}`
   修改慢病专项档案。

6. `DELETE /app/chronic-diseases/{profileId}`
   逻辑删除慢病专项档案。

## 4. 详情看板聚合口径

详情接口返回 `ChronicDiseaseDashboardDTO`，包含四类信息：

1. `profile`：用户维护的慢病专项档案。
2. `indicatorTrends`：从最近 12 份报告中匹配出来的重点指标趋势。
3. `abnormalProblemCount`：该成员当前未关闭、且命中病种指标配置的健康问题数量。
4. `activeMedicationPlanCount`：该成员当前启用中的用药计划数量。

趋势匹配规则：

1. 先按 `focus_indicator_codes_json` 匹配 `report_item.standard_item_code` 和 `report_item.item_code`。
2. 如果编码未命中，再按 `focus_indicator_keywords_json` 匹配 `report_item.item_name`。
3. 每个指标按报告日期升序组装趋势点。
4. 变化方向只基于结果值里的首个数字做轻量判断，不输出医学结论。

## 5. App 接入

App 工作台新增“慢病专项”标签，页面能力包括：

1. 拉取慢病病种配置和家庭成员列表。
2. 查看慢病专项档案列表。
3. 新增、编辑、删除专项档案。
4. 打开专项详情，看重点指标趋势、相关问题数量、用药计划数量和后端摘要。

App 页面只传 `diseaseCode`，不写死病种逻辑。后续新增慢病时，只要接口返回新的病种配置，新增表单就能选择该病种。

## 6. 边界

本期不做以下内容：

1. 不做医学诊断或治疗建议。
2. 不做单病种专属页面分支。
3. 不做实时设备指标采集。
4. 不做医生端协作。
5. 不把慢病专项与会员强绑定，后续如果需要限制高级趋势或 AI 月报，可以再接会员门禁 `gateCode`。

## 7. 后续扩展

建议下一步扩展：

1. 后台维护病种配置页面。
2. 慢病专项复查任务一键创建。
3. 慢病专项月报，聚合报告趋势、服药依从性和异常问题闭环。
4. 病种配置支持目标范围，例如血压目标、HbA1c 目标。
5. 对接会员门禁，高级趋势、长期月报和家庭成员数量可做会员权益。
