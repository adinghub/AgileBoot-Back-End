# 健康系统数据库初始化文档

## 1. 文档目的

本文档用于明确当前仓库的数据库初始化口径，确保新环境可以直接按“最终结构”完成 PostgreSQL 初始化，不再执行历史增量 SQL。

当前文档以 2026-04-25 仓库实现为准。


## 2. 当前初始化原则

当前数据库初始化统一遵循以下原则：

1. 运行时数据库为 PostgreSQL。
2. 不再额外创建 `app` schema，直接使用 PostgreSQL 默认 schema。
3. 健康业务表全部使用最终业务表名，不使用 `health_*` 前缀。
4. 当前数据库尚未正式部署、没有业务数据，因此不提供迁移脚本，只保留最终初始化脚本。
5. 后续新增功能如果需要补数据或补结构，再单独新增新的 PostgreSQL 增量脚本。


## 3. 初始化脚本清单

### 3.1 一体化初始化脚本

1. `sql/pgsql/健康系统_schema_20260423.sql`

该脚本已经直接包含以下内容：

1. 基础系统表结构
2. 基础系统种子数据
3. 健康业务表结构
4. 健康业务默认数据

因此新环境初始化时，不再需要额外先执行 `healthtrail_schema.sql`、`healthtrail_data.sql`。

### 3.2 后台菜单脚本

最后执行后台菜单权限脚本：

1. `sql/pgsql/健康系统_后台管理菜单权限_20260423.sql`


## 4. 推荐初始化顺序

新环境推荐严格按以下顺序执行：

1. `sql/pgsql/健康系统_schema_20260423.sql`
2. `sql/pgsql/健康系统_后台管理菜单权限_20260423.sql`

原因：

1. 第 1 步已经同时创建基础系统表、基础种子数据、健康业务表和健康业务默认数据。
2. 第 2 步依赖 `sys_menu`、`sys_role_menu` 等基础表，因此仍然放在总脚本之后执行。
3. 当前不需要再补跑任何 `ALTER TABLE` 风格的历史脚本。

## 7. 不再执行的旧脚本口径

当前仓库不再推荐执行任何历史增量脚本来补齐药品库存、单位、附件能力。

原因：

1. 当前数据库还没有正式部署，不需要迁移兼容。
2. 旧增量脚本仍带有历史表名或历史拆分思路，容易误导执行顺序。
3. 统一执行最终初始化脚本更稳妥，也更符合当前项目阶段。
4. 基础系统脚本内容已经并入 `健康系统_schema_20260423.sql`，新环境不再需要单独执行基础 `healthtrail_*` 初始化脚本。


## 8. 初始化完成后的核对方式

### 8.0 和代码实体的核对口径

本初始化脚本已经按当前 Java 实体做过表结构核对，后续如果继续调整实体，建议按以下规则同步 SQL：

1. `@TableName` 对应的 29 张实体表均应存在于默认 schema 中。
2. `Long + IdType.AUTO` 的主键使用 `BIGSERIAL` 或 PostgreSQL 等价的 `serial8`。
3. `Integer + IdType.AUTO` 的主键使用 `SERIAL`，当前包括 `sys_config.config_id` 和 `sys_notice.notice_id`。
4. `@TableField(exist = false)` 是运行时临时字段，不应在数据库建列；例如 `DrugEntity.stockQuantity` 由 `drug_stock_batch` 实时汇总，不落到 `drug` 主表。
5. `sys_role_menu` 是角色和菜单关系表，虽然实体上 `role_id` 保留了 `IdType.AUTO` 历史注解，但数据库仍按业务关系使用 `(role_id, menu_id)` 复合主键，不把 `role_id` 单独做自增。

### 8.1 检查健康业务表

```sql
SELECT tablename
FROM pg_tables
WHERE schemaname = current_schema()
  AND tablename IN (
      'app_user',
      'family_member',
      'attachment',
      'drug_unit',
      'drug',
      'drug_stock_batch',
      'drug_stock_log',
      'medication_plan',
      'medication_reminder',
      'report',
      'report_item',
      'app_device',
      'app_message',
      'follow_up_task',
      'follow_up_task_log',
      'operation_task',
      'family_member_share',
      'family_share_invite',
      'indicator_template'
  )
ORDER BY tablename;
```

### 8.2 检查药品关键字段

```sql
\d attachment
\d drug_unit
\d drug
\d drug_stock_batch
\d drug_stock_log
```

重点检查字段：

1. `drug.stock_unit_id`
2. `drug.stock_unit`
3. `drug.image_attachment_id`
4. `drug.stock_alert_threshold`
5. `drug_stock_batch.batch_no`

### 8.3 检查初始化种子数据

```sql
SELECT COUNT(*) AS unit_count FROM drug_unit;
SELECT drug_id, owner_user_id, drug_name, stock_unit_id, stock_unit
FROM drug
ORDER BY drug_id;
```

预期结果：

1. `drug_unit` 至少 8 条
2. `drug` 至少 2 条系统药品示例
3. 系统药品示例的 `stock_unit_id` 已回填

### 8.4 检查后台菜单

```sql
SELECT menu_id, menu_name, parent_id, path, permission
FROM sys_menu
WHERE path LIKE '/health%'
   OR permission LIKE 'health:%'
ORDER BY menu_id;
```


## 9. 默认数据库建议

建议数据库使用：

1. 数据库名：`healthtrail`
2. 用户名：`postgres`
3. 端口：`5432`
4. schema：默认 schema（通常为 `public`）

参考连接串：

```text
jdbc:postgresql://localhost:5432/healthtrail
```


## 10. 当前执行口径总结

后续开发、测试、部署统一按以下口径执行：

1. PostgreSQL 是唯一正式数据库口径。
2. 数据库对象直接落在默认 schema，不再额外维护 `app` schema。
3. 基础系统表和健康业务表统一执行 `sql/pgsql/健康系统_schema_20260423.sql` 这一份一体化初始化脚本。
4. 后台健康菜单再执行 `sql/pgsql/健康系统_后台管理菜单权限_20260423.sql`。
5. 不再混用旧的 `health_*` 历史脚本、MySQL 原始脚本和拆分增量脚本。
