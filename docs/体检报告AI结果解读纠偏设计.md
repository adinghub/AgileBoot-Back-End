# 体检报告 AI 结果解读纠偏设计

## 1. 背景

App 端“报告解读”能力当前由 `HealthReportResultInterpretationGenerator` 负责生成。
这条链路会优先调用外部大模型，把结构化指标转成更自然的中文说明，再落库到 `health_report.result_interpretation`。

线上发现一类明显错误示例：

- 指标：`结核杆菌γ-干扰素检测`
- 结果值：`0.92 pg/ml`
- 参考范围：`0 - 14 pg/ml`
- 实际结论应为：`处于参考范围内`
- 错误文案却写成：`高于正常参考范围`

这类错误非常伤用户信任，因为它不是医学边界问题，而是基础数值比较都说反了。

## 2. 问题定位

本次排查发现：

1. 结构化落库的 `abnormalFlag=1` 实际代表的是 `NORMAL`，并不是“偏高”。
2. 本地兜底文案分支本身按 `abnormalFlag` 生成，方向逻辑没有问题。
3. 问题出在“外部大模型结果解读”阶段：
   - 输入里虽然给了 `abnormalFlag`、参考范围、结果值；
   - 但提示词没有强约束模型必须服从后端已经计算出的状态；
   - 模型会再次自行推断，导致偶发把正常项写成“高于参考范围”。

换句话说，这不是解析层数值判断错了，而是“自然语言解读层”发生了二次误判。

## 3. 设计目标

本次修复的目标不是让模型“尽量更准”，而是先保证：

1. 后端已经算出的方向性结论不能被模型推翻。
2. 一旦模型输出与结构化判定冲突，用户最终看不到错误文案。
3. 保留外部大模型的自然语言优势，但把风险收敛在可控范围内。

## 4. 方案设计

### 4.0 多附件合并理解

在线上真实使用里，用户可能为同一个检查项目上传多个附件，例如：

1. 明细页和结论页分开上传
2. 检查单上下半页分别截图
3. 对照项、补充页、说明页单独成图

因此大模型在做结构化解析和结果解读时，不能默认“一个附件 = 一份独立报告”。

本次提示词中新增明确约束：

1. 同一次调用收到的文本/图片，可能来自同一检查项目的多个附件或多页内容
2. 模型必须先做合并理解，再输出统一结构化结果
3. 对重复项目要做去重，优先保留信息更完整的一条
4. 结果解读也必须把这些附件视作同一次检查的不同部分，而不是多次独立检查

这样可以减少下面这类问题：

1. 明细项在附件 A，参考范围在附件 B，模型因为没合并而误判
2. T/N/P 对照项分散在不同截图，模型没拼起来，导致算法依赖型指标无法判读
3. 同一项目在多页重复出现，被模型错误输出成两条不同指标

### 4.1 给模型显式补充机器判定状态

为每条结构化指标新增两类上下文字段传给大模型：

- `abnormalFlagName`：例如 `正常 / 偏高 / 偏低 / 异常 / 待判断`
- `computedStatus`：例如 `NORMAL / HIGH / LOW / ABNORMAL / UNKNOWN`

这样模型不需要再从 `0/1/2/3/4` 这样的数字自行猜语义，也不需要只凭结果值和参考范围做二次推理。

### 4.2 强化提示词约束

在系统提示词里增加硬规则：

1. 必须严格服从 `computedStatus / abnormalFlagName`
2. 对所有带数字的结果，尤其是带小数的结果，必须按数学大小比较参考范围，不能凭直觉判断
3. `NORMAL` 绝不能写成“高于参考范围 / 低于参考范围 / 超出范围”
4. `HIGH` 只能描述为偏高方向
5. `LOW` 只能描述为偏低方向
6. `UNKNOWN` 不允许擅自推断高低

这里专门强调了小数场景，是因为像 `0.92`、`0.08`、`13.7` 这类值，
模型有时会因为“看起来不像常见整数结果”而产生错误联想。
因此提示词里增加了明确示例：`0.92` 相对 `0-14` 必须判定为范围内。

除此之外，本次新增了“无参考范围指标”的分型约束：

1. 当结构化结果没有提供参考范围时，模型必须先识别指标类型：
   - 算法依赖型
   - 固定阈值型
   - 动态变化型
   - 描述型
2. 算法依赖型指标应先检查当前报告内是否已经给出完成判读所需的配套参数
3. 如果当前报告内参数齐全，可以基于同页相关指标做联合判定
4. 如果当前报告内关键参数仍然不全，才不能直接输出正常/异常
5. 固定阈值型指标如果当前输入里没有阈值依据，也不能擅自补阈值
6. 动态变化型缺少历史值时，不能下趋势结论
7. 描述型指标应强调临床结合，不能硬写成确定性疾病判断

这样做的原因是，很多报告单并不会直接给出参考范围。
例如 IGRA、OGTT、eGFR、部分血气和复合判读项目，真正结论依赖的是公式、对照项或组合逻辑，
并不是拿“单个数值”就能稳妥判断。

但这里还有一个重要边界：

1. 如果同一张报告已经给出了配套指标，例如 T/N/P 对照、空腹与餐后结果、同组组合项
2. 那么模型应该优先利用“当前报告内已给出的其他结构化指标”做联合判断
3. 只有当前报告内仍缺少关键条件时，才回退到“该指标不能仅凭单一数值解读，需要医生结合临床判断”

### 4.2.1 无知识库前提下的边界控制

当前系统没有接入外部医学知识库，因此提示词里进一步明确：

1. 模型不能把“自己记忆中的阈值”当成系统事实输出
2. 不能为输入里没给出的参考范围、公式、算法条件做确定性补写
3. 允许利用当前报告中已经结构化给出的其他指标做保守联动推理
4. 对缺少判读依据的条目，宁可保守提示“需结合原始报告或医生判断”，也不能编造明确异常结论

这样即使模型继续生成自然语言，也是在受限轨道里表达。

### 4.3 增加输出一致性校验

仅靠提示词不能完全消除大模型幻觉，因此在模型返回后，再增加一次后端校验。

当前版本优先拦截三类高风险矛盾：

1. 正常项被写成“高于/低于参考范围”
2. 偏高项被写成“偏低/降低”
3. 偏低项被写成“偏高/升高”

一旦命中矛盾：

- 直接丢弃外部模型结果
- 回退到本地规则化文案
- 记录 warn 日志，方便后续继续观察模型表现

### 4.4 为什么选择“回退”而不是“局部替换”

本次没有在错误文案里做字符串级替换，原因有三点：

1. 局部替换很容易留下上下文残缺，导致语句读起来别扭。
2. 当前解读是分段自然语言，不同句子之间存在上下文关联，硬替换风险更大。
3. 本地规则文案已经具备稳定性，回退成本低、可解释性强。

因此本次优先选择“整段回退”，让最终展示结果先回到可信状态。

## 5. 影响范围

本次改动影响文件：

- `healthtrail-domain/src/main/java/com/healthtrail/domain/health/report/parser/HealthReportResultInterpretationGenerator.java`

影响链路：

1. 报告解析完成后刷新 `resultInterpretation`
2. 报告详情页查看“结果解读”

不影响：

1. `report_item` 行级结构化数据落库
2. 指标解读 `itemInterpretation`
3. AI 总结 `aiSummaryContent`

## 6. 预期结果

修复后，对于：

- 结果值：`0.92`
- 参考范围：`0 - 14`
- `abnormalFlag = NORMAL`

系统应满足：

1. 外部模型若输出“高于参考范围”等冲突文案，会被后端拦截。
2. 最终展示给用户的“结果解读”会回退到本地规则文本，方向保持正确。
3. 用户不再看到“0.92 高于 0-14”这类明显错误。

## 7. 后续建议

后续如果要继续提升稳定性，可以考虑：

1. 把“解读输出”从自由文本改成结构化 JSON，再由后端拼文案；
2. 为重点指标增加专项模板，减少大模型自由发挥空间；
3. 对线上模型输出增加抽样巡检日志，持续优化关键词校验规则。
