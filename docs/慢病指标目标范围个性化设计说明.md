# 慢病指标目标范围个性化设计说明

## 1. 背景

慢病专项已经支持所有慢病病种，并能按照病种配置从近期报告中聚合重点指标趋势。下一步需要解决的是个人目标差异问题：同一个病种、同一个指标，在不同成员、不同年龄段、不同医嘱下，目标范围可能不一致。

如果只依赖病种默认配置，会出现两个问题：

1. 目标过于粗糙，无法表达用户自己的医嘱范围。
2. App 只能展示报告里的异常标记，不能告诉用户“这个指标是否达到个人管理目标”。

因此新增“慢病专项指标目标范围”能力，让用户可以在某个慢病档案下维护具体指标的目标下限、上限或文字说明。

## 2. 目标

本轮实现聚焦三件事：

1. 在慢病专项档案下保存指标个人目标范围。
2. 慢病详情看板返回趋势时，同步给出最新值与个人目标的比对结果。
3. App 在趋势卡展示目标状态，并支持从趋势卡快速调整目标。

本轮不做的内容：

1. 不覆盖体检报告原始指标值。
2. 不把目标写进病种默认配置。
3. 不做医学诊断结论，只做用户维护目标与报告最新值之间的辅助比对。

## 3. 数据模型

新增表：`health_chronic_indicator_target`

核心字段：

| 字段 | 说明 |
| --- | --- |
| `target_id` | 指标目标主键 |
| `owner_user_id` | 归属 App 用户 |
| `member_id` | 家庭成员 |
| `profile_id` | 慢病专项档案 |
| `indicator_code` | 指标编码，优先使用标准指标编码 |
| `indicator_name` | 指标名称快照 |
| `target_min` | 目标下限，空值表示不限制下限 |
| `target_max` | 目标上限，空值表示不限制上限 |
| `target_text` | 非数值型目标说明 |
| `result_unit` | 指标单位快照 |
| `status` | 状态，1 启用，0 停用 |

唯一约束：

- 同一 `profile_id + indicator_code` 在未删除状态下只保留一条当前目标。

这样用户从趋势卡反复调整同一指标目标时，会更新原目标，而不是生成多条互相冲突的目标范围。

## 4. 后端运行流程

慢病详情看板的运行流程调整为：

1. 加载慢病专项档案，并校验成员访问权限。
2. 加载病种配置，得到重点指标编码和关键词。
3. 加载该专项下启用中的指标目标范围。
4. 加载近期报告及报告指标。
5. 按病种配置匹配重点指标趋势。
6. 用趋势指标编码命中个人目标范围。
7. 对最新值做目标比对，并返回目标状态与说明。

目标状态包括：

| 状态 | 含义 |
| --- | --- |
| `IN_RANGE` | 最新值进入目标范围 |
| `BELOW` | 最新值低于目标范围 |
| `ABOVE` | 最新值高于目标范围 |
| `TEXT_ONLY` | 只维护了文字目标，无法做数值比对 |
| `UNMEASURABLE` | 最新值暂无法解析为数值 |

## 5. App 使用方式

慢病详情看板新增两个展示点：

1. 顶部摘要增加“目标范围”数量。
2. 指标趋势卡展示目标比对结果，并提供“设置个人目标/调整个人目标”动作。

用户填写内容：

1. 目标下限，可空。
2. 目标上限，可空。
3. 目标说明，可空。

保存时要求至少填写一项，避免生成没有业务含义的空目标。

## 6. 边界说明

1. 个人目标只影响慢病看板展示，不影响报告解析结果。
2. 个人目标只挂在专项档案下，不作为全局病种默认目标。
3. 非数值型目标只展示说明，不做达标判断。
4. 数值判断只从报告结果中提取第一个可识别数字，复杂表达后续可再扩展标准化解析。

## 7. 已落地范围

后端已落地：

1. 指标目标范围实体、仓储、保存和删除能力。
2. 慢病看板趋势目标命中与状态比对。
3. PostgreSQL 增量脚本。

App 已落地：

1. 慢病看板模型解析目标范围。
2. 趋势卡展示目标状态与说明。
3. 趋势卡快速维护个人目标。

## 8. 后续可扩展

1. 在后台病种配置中维护默认目标模板，用户建档时自动带出初始目标。
2. 增加目标变更历史，展示每次调整前后的范围和原因。
3. 为目标偏离生成待跟进任务，形成“发现偏离 -> 设置干预 -> 复查确认”的闭环。
4. 增加更多数值解析能力，支持区间、阴性/阳性、分级结果等复杂报告表达。
