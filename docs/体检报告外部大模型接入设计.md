# 体检报告外部大模型接入设计

## 1. 目标

本设计用于给体检报告 AI 智能总结扩展“外部大模型接入能力”，满足以下目标：

1. 在不破坏现有 App 协议的前提下接入第三方模型
2. 优先输出更自然、更可读的中文健康管理总结
3. 在外部模型未配置或调用失败时自动回退到本地规则总结
4. 让后续切换供应商时只改配置和客户端细节，不改业务主流程

## 2. 当前实现位置

当前能力已经落地到以下文件：

1. `healthtrail-domain/src/main/java/com/healthtrail/domain/health/report/config/HealthReportExternalLlmProperties.java`
2. `healthtrail-domain/src/main/java/com/healthtrail/domain/health/report/llm/HealthReportExternalLlmClient.java`
3. `healthtrail-domain/src/main/java/com/healthtrail/domain/health/report/HealthReportApplicationService.java`
4. `healthtrail-api/src/main/resources/application.yml`

## 3. 接入协议选择

当前统一按 OpenAI 兼容的 Chat Completions 协议接入。

当前默认推荐接入智谱 GLM：

1. 模型：`glm-4.6v-flash`
2. 接口：`https://open.bigmodel.cn/api/paas/v4/chat/completions`
3. 鉴权：`Authorization: Bearer <API_KEY>`

这样做的原因是：

1. 智谱 GLM、OpenAI、DeepSeek 和很多中转网关都支持类似协议
2. 后端只维护一套请求和响应解析逻辑即可
3. 目前业务只需要文本总结，不涉及工具调用或多模态输入

## 4. 调用链路

当前 AI 总结调用链路如下：

1. `HealthReportApplicationService.generateAiSummary(...)` 负责组织业务上下文
2. 应用服务先计算分析摘要、异常建议、趋势结果和用药计划数量
3. 构造“系统提示词 + 用户提示词”
4. 调用 `HealthReportExternalLlmClient.generateSummary(...)`
5. 若外部模型返回有效文本，则写入 `ai_summary_content`
6. 若外部模型未启用、配置不完整或调用失败，则回退到本地规则总结
7. 返回 `disclaimer` 告知前端总结来源

## 5. 配置项说明

配置前缀：

`health.report.ai.external-llm`

支持的配置项如下：

1. `enabled`
   - 是否启用外部大模型
2. `provider-name`
   - 供应商名称，仅用于日志和免责声明展示
3. `api-url`
   - Chat Completions 接口地址
4. `api-key`
   - 鉴权密钥
5. `model`
   - 模型名称
6. `temperature`
   - 温度参数，默认 `0.2`
7. `max-tokens`
   - 最大输出 token 数
8. `timeout-ms`
   - HTTP 超时时间
9. `headers`
   - 额外透传请求头
10. `system-prompt`
   - 自定义系统提示词，未配置时使用代码内置默认提示词

## 6. 提示词与数据边界

### 6.1 系统提示词

系统提示词默认要求模型：

1. 只基于结构化体检报告数据做总结
2. 输出中文自然语言正文
3. 不给出确诊结论
4. 不代替医生开药

### 6.2 用户提示词

用户提示词会组织成 JSON 上下文，核心字段包括：

1. 成员姓名
2. 报告名称
3. 报告类型
4. 报告日期
5. 分析摘要
6. 异常项列表
7. 异常建议列表
8. 趋势变化列表
9. 启用中的用药计划数量

### 6.3 数据最小化原则

当前不会把整份原始报告全文无限制透传给第三方模型，只发送已经清洗过的关键结构化上下文。

这样做是为了：

1. 控制成本
2. 提高稳定性
3. 降低不必要的数据外发范围

## 7. 回退策略

以下任一情况发生时，系统都会自动回退到本地规则总结：

1. `enabled = false`
2. `api-url / api-key / model` 有任一未配置
3. 外部接口超时
4. 外部接口返回非 2xx 状态码
5. 响应结构无法提取有效文本
6. 调用过程抛出运行时异常

这意味着：

1. 外部模型能力是增强项，不是单点依赖
2. 即使第三方供应商波动，App 和后台管理端依然可正常展示 AI 总结结果

## 8. 免责声明设计

当前返回给前端的 `disclaimer` 分两类：

1. 外部模型生成
   - 文案中会带上 `provider-name`
2. 本地规则总结
   - 文案明确说明是基于结构化指标、趋势变化和规则建议自动生成

这样做的目的是让：

1. App 用户知道当前结果只用于健康管理提醒
2. 业务同学能快速判断当前结果是否用了外部模型增强

## 9. 配置示例

参考 `healthtrail-infrastructure/src/main/resources/application-basic-*.yml` 中的样例：

```yaml
health:
  report:
    ai:
      external-llm:
        enabled: true
        provider-name: Zhipu-GLM
        api-url: https://open.bigmodel.cn/api/paas/v4/chat/completions
        api-key: ${HEALTH_REPORT_EXTERNAL_LLM_API_KEY:${ZHIPU_API_KEY:}}
        model: glm-4.6v-flash
        supports-image-input: true
        temperature: 0.2
        max-tokens: 700
        timeout-ms: 15000
```

推荐环境变量：

1. `HEALTH_REPORT_EXTERNAL_LLM_API_KEY`
2. `ZHIPU_API_KEY`
3. `HEALTH_REPORT_EXTERNAL_LLM_MODEL`

## 10. 验收建议

建议按以下顺序验收：

1. 关闭 `enabled`，确认 AI 总结仍可正常返回本地规则结果
2. 补齐配置并启用，确认 AI 总结能够返回外部模型增强结果
3. 人为配置错误的 `api-url` 或 `api-key`，确认接口仍能自动回退，不影响主链路
4. 观察 `disclaimer` 是否能正确反映总结来源
