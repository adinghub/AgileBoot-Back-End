# 后台体检报告管理设计

## 1. 功能目标

本功能用于给后台管理端提供“体检报告全链路运维入口”，覆盖以下场景：

1. 分页查询体检报告
2. 查看报告详情和结构化指标
3. 查看规则分析摘要
4. 查看异常建议
5. 查看趋势对比
6. 后台重新生成 AI 智能总结
7. 删除体检报告

## 3. 设计原则

### 3.1 后台优先复用 App 已稳定的分析链路

后台这里没有单独再造一套“报告分析实现”，而是尽量复用 `HealthReportApplicationService` 里已经跑通的能力：

1. 报告详情
2. 指标列表
3. 分析摘要
4. 异常建议
5. 趋势对比
6. AI 智能总结

这样可以避免后台和 App 两边出现分析结果不一致的问题。

### 3.2 后台只补“全局入口”和“运维动作”

后台新增的是：

1. 全局分页列表入口
2. 一次性拉全详情的管理弹窗
3. AI 总结重生成按钮
4. 删除报告按钮

## 4. 接口设计

### 4.1 报告列表

- 接口：`GET /health/reports`
- 权限：`health:report:list`

查询参数：

1. `pageNum`
2. `pageSize`
3. `ownerUserId`
4. `memberId`
5. `reportType`
6. `parseStatus`
7. `keyword`

### 4.2 报告详情能力

以下接口统一使用 `health:report:query` 权限：

1. `GET /health/reports/{reportId}`
2. `GET /health/reports/{reportId}/items`
3. `GET /health/reports/{reportId}/analysis`
4. `GET /health/reports/{reportId}/advice`
5. `GET /health/reports/{reportId}/trends`

### 4.3 AI 智能总结重生成

- 接口：`POST /health/reports/{reportId}/ai-summary`
- 权限：`health:report:ai`

说明：

1. 当前实现优先调用外部大模型
2. 若外部大模型不可用，则自动回退到本地规则总结
3. 返回结果里会携带 `disclaimer`，说明当前总结来源

### 4.4 删除报告

- 接口：`DELETE /health/reports/{reportId}`
- 权限：`health:report:remove`

说明：

1. 删除报告时会同步逻辑删除该报告下的结构化指标结果
2. 当前不物理删除上传文件，便于后续审计与恢复

## 5. 页面设计

### 5.1 搜索区

后台搜索区支持：

1. 主账号 ID
2. 成员 ID
3. 报告类型
4. 解析状态
5. 关键字

### 5.2 列表区

列表页重点展示：

1. 报告是谁的
2. 报告类型和日期
3. 当前解析状态
4. AI 总结状态
5. 分析摘要

### 5.3 详情弹窗

详情弹窗一次性并列展示：

1. 报告基础信息
2. 分析摘要
3. 异常建议
4. 趋势对比
5. 指标列表

这样后台在处理“为什么用户看到的总结不对”“某个指标是否真的异常”等问题时，不需要逐个接口点开。

## 6. OCR 与 AI 边界

本期边界如下：

1. OCR 仍保留占位能力，不在后台额外提供真实 OCR 管理入口
2. AI 智能总结已经支持外部大模型扩展
3. 后台管理端当前只提供“重新生成 AI 总结”，不提供 OCR 重跑入口

## 7. 权限设计

页面对应权限如下：

1. 列表：`health:report:list`
2. 详情：`health:report:query`
3. AI 总结：`health:report:ai`
4. 删除：`health:report:remove`

## 8. 验收建议

建议按以下步骤验收：

1. 进入页面，确认分页列表可正常打开
2. 查看详情，确认基础信息、指标、分析、建议、趋势全部加载
3. 触发 AI 智能总结，确认成功后列表和详情同步刷新
4. 删除一份报告，确认列表刷新且详情接口不可再访问
