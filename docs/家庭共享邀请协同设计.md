# 家庭共享邀请协同设计

## 1. 目标

本设计用于补齐 App 二期里的“家庭增强”能力，让一个家庭成员不再只属于单个账号可见，而是支持：

1. 主账号为成员生成共享邀请码
2. 其他 App 账号输入邀请码加入协同
3. 共享成员进入成员列表、用药、报告等业务链路
4. 区分主账号、协同管理、只读查看三类权限

## 2. 角色定义

### 2.1 OWNER

主账号，即创建该家庭成员的账号。

具备能力：

1. 查看成员详情
2. 修改成员资料
3. 删除成员
4. 创建共享邀请码
5. 查看协同账号和邀请码记录
6. 移除协同账号
7. 维护该成员的用药计划、提醒、体检报告

### 2.2 EDITOR

协同管理账号。

具备能力：

1. 查看成员详情
2. 修改成员资料
3. 维护该成员的用药计划、提醒、体检报告

不具备能力：

1. 删除成员
2. 创建/取消邀请码
3. 移除其他协同账号

### 2.3 VIEWER

只读查看账号。

具备能力：

1. 查看成员详情
2. 查看该成员的用药、报告和趋势结果

不具备能力：

1. 修改成员资料
2. 反馈提醒结果
3. 上传/删除报告
4. 修改用药计划

## 3. 数据模型

### 3.1 共享关系表 `health_family_member_share`

用于记录已经生效的共享关系。

关键字段：

1. `member_id`
2. `owner_user_id`
3. `collaborator_user_id`
4. `share_role`
5. `share_status`
6. `accepted_time`

### 3.2 邀请表 `health_family_share_invite`

用于记录共享邀请过程。

关键字段：

1. `invite_code`
2. `member_id`
3. `owner_user_id`
4. `invitee_user_id`
5. `share_role`
6. `invite_status`
7. `expire_time`
8. `accepted_time`

## 4. 权限实现策略

当前版本新增统一访问控制服务 `FamilyMemberAccessService`，供家庭成员、用药、报告模块共同复用。

统一策略：

1. 家庭成员列表返回“我的成员 + 共享成员”
2. 成员详情按访问上下文返回 `accessSource`、`accessRole`、`isOwner`、`canEdit`
3. 用药计划、提醒、报告不再只按 `owner_user_id` 过滤，而是按“当前账号可访问的 member_id 集合”过滤
4. 写操作统一要求 `canEdit = true`
5. 删除成员、管理邀请码、管理协同账号统一要求 `isOwner = true`

## 5. 业务流程

### 5.1 创建邀请码

1. 主账号进入某个成员的共享管理
2. 选择角色 `EDITOR` 或 `VIEWER`
3. 系统生成 8 位邀请码
4. 邀请默认 72 小时有效

### 5.2 接受邀请码

1. 另一个账号输入邀请码
2. 后端校验邀请码存在、状态为待接受、未过期、不是主账号自己
3. 写入共享关系表
4. 邀请状态改为已接受
5. 该成员自动进入共享账号的成员列表和业务选择器

## 6. 对其他模块的影响

### 6.1 家庭成员模块

新增字段：

1. `accessSource`
2. `accessSourceName`
3. `accessRole`
4. `accessRoleName`
5. `isOwner`
6. `canEdit`

### 6.2 用药模块

影响：

1. 共享成员可进入计划筛选和提醒筛选
2. `EDITOR` 可维护计划与提醒反馈
3. `VIEWER` 只读查看

### 6.3 报告模块

影响：

1. 共享成员可查看报告、趋势、OCR/AI 占位结果
2. `EDITOR` 可上传、删除、维护指标
3. `VIEWER` 只读查看

## 7. 风险与后续建议

当前版本采用邀请码方式，适合快速落地联调。

后续可继续扩展：

1. 站内消息邀请
2. 手机号定向邀请
3. 邀请失效自动清理
4. 协同操作日志审计
