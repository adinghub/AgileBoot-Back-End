# 体检报告上传设计

## 1. 功能目标

体检报告模块当前阶段已经从“只做文件归档”扩展成“上传后可继续分析和消费”的完整闭环：

1. App 用户上传报告文件
2. 报告绑定到具体家庭成员
3. 支持报告列表、详情、删除
4. 支持结构化指标保存、异常分析、趋势对比与 AI 总结


## 2. 设计范围

### 2.1 当前实现

当前已支持：

1. 报告文件上传
2. 报告元信息保存
3. 报告分页列表
4. 报告详情
5. 报告逻辑删除
6. 指标结果整份保存
7. 指标异常自动判定
8. 报告分析摘要
9. 报告异常建议
10. 报告趋势对比
11. AI 智能总结
12. 后台体检报告管理
13. 后台指标模板维护

### 2.2 当前边界

当前仍保留以下边界：

1. OCR 仍保留占位能力，尚未接入真实图片 / PDF 识别
2. 报告分享
3. 后台人工审核结果流转

### 3.2 解析状态

解析状态继续保留，方便后续扩展：

1. `0`：待解析
2. `1`：解析中
3. `2`：已解析
4. `3`：解析失败


## 4. 关键业务规则

### 4.1 报告必须绑定家庭成员

健康系统里的报告不是单纯挂在账号下，而是必须绑定到成员。

这样后续：

1. 异常分析
2. 用药联动
3. 首页健康摘要
4. 成员维度健康档案

都能围绕同一个主体展开。

### 4.2 文件与元信息分开处理

上传时会先落文件，再写数据库元信息。

数据库中只保存：

1. 文件访问地址
2. 存储文件名
3. 原始文件名
4. 文件大小和后缀

这样后续迁移到 OSS 或对象存储时，业务表结构不需要大改。

### 4.3 删除采用逻辑删除

当前删除只做逻辑删除，不直接物理删除文件。

原因：

1. 避免误删后完全不可恢复
2. 便于后续补解析任务
3. 便于审计与排查

### 4.4 上传完成后继续走结构化分析链路

报告上传成功后，后续可以继续通过独立接口完成：

1. 指标结果保存
2. 异常判定与摘要重算
3. 报告建议生成
4. 趋势对比
5. AI 智能总结

这样上传链路和分析链路解耦，前后端更容易分阶段联调。
