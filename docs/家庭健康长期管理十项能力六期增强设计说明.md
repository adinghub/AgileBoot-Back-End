# 家庭健康长期管理十项能力六期增强设计说明

## 1. 背景

前五期已经把家庭健康长期管理的十项能力聚合到同一个视图里，并补齐了下一步建议、指标趋势、用药规则、照护分派、资料包长图和脱敏分享等增强能力。

随着家庭成员增多，用户看到的是多类事项的横向列表，例如复查建议、目标趋势、照护任务和手动指标趋势。但真实使用时，用户更常问的是：

- 今天应该先关注哪个家庭成员？
- 哪个成员同时存在复查、目标趋势或照护任务？
- 哪些成员当前比较平稳，只需要继续观察？

因此六期不再增加新的长期管理事项，而是在现有数据上增加一层“成员关注摘要”，把已经算好的长期管理结果按家庭成员收口。

## 2. 目标

六期目标是让长期管理区能够按成员展示关注优先级：

1. 后端基于本次长期管理对象中已有的下一步建议、复查建议、目标趋势、照护任务和手动指标趋势进行聚合。
2. App 展示“成员关注”入口、关注成员数量、成员关注预览和底部详情弹窗。
3. 不新增表，不新增后台任务，不自动生成照护事项。
4. 不改变原有十项能力的判断口径，只增加一个更适合家庭场景的阅读维度。

## 3. 数据口径

成员关注摘要只使用当前长期管理结果中已经存在的数据：

- `nextActionHints`：统计成员关联的下一步建议数量，并复用其中的优先级权重。
- `reviewSuggestions`：统计成员关联的复查建议数量。
- `indicatorTargetTrends`：只统计高于目标、低于目标或暂不可衡量的目标趋势。
- `careCollaboration.pendingTasks`：统计成员关联的待处理照护任务。
- `dailyIndicatorBoard.trendSummaries`：只统计近期有上升或下降变化的手动指标趋势。

成员关注摘要不会重新读取成员、慢病、报告、任务或日记明细。这样可以保证六期增强不会把长期管理首屏的查询成本再次放大。

## 4. 后端实现

后端在长期管理聚合对象中新增：

```java
private List<MemberFocusSummaryDTO> memberFocusSummaries = new ArrayList<>();
```

`MemberFocusSummaryDTO` 包含：

- `memberId`：家庭成员 ID。
- `memberName`：家庭成员名称。
- `riskLevel`：该成员当前最高关注等级。
- `priorityWeight`：排序用权重。
- `nextActionCount`：下一步建议数量。
- `reviewSuggestionCount`：复查建议数量。
- `targetWarningCount`：目标趋势关注点数量。
- `careTaskCount`：待处理照护任务数量。
- `medicationRuleCount`：用药规则数量预留字段。
- `dailyTrendCount`：手动指标趋势数量。
- `summary`：成员关注摘要文案。
- `tags`：短标签，例如复查、目标、照护、趋势或平稳观察。

核心聚合方法为 `buildMemberFocusSummaries(...)`。该方法先为家庭成员创建默认摘要，再从长期管理对象中的已计算结果回填计数和风险等级，最后按 `priorityWeight` 与 `nextActionCount` 排序取前 8 个成员。

## 5. App 实现

App 在长期管理模型中新增 `memberFocusSummaries` 字段，并新增 `MemberFocusSummary` 解析模型。

长期管理区增加三处展示：

1. 操作区新增“成员关注”按钮。
2. 指标区新增“关注成员”数量。
3. 内容区新增前三个成员关注预览。

点击“成员关注”后，App 使用底部弹窗展示所有成员关注摘要。弹窗只展示后端已经聚合好的摘要和标签，不在页面侧重新遍历十项能力明细，避免展示口径和后端排序规则不一致。

## 6. 边界

六期明确不做以下事情：

1. 不新增长期管理能力编号。
2. 不新增数据库表。
3. 不自动创建复查任务或照护任务。
4. 不把成员关注结果持久化。
5. 不把用药规则强行归属到成员，当前用药规则只有计划 ID，缺少稳定成员维度时保持预留计数为 0。

## 7. 预期收益

六期完成后，家庭长期管理不再只是一组事项列表，还能快速回答“哪个成员更需要优先看”。

对用户的价值：

- 家庭成员较多时，能更快找到关注重点。
- 平稳成员和有风险成员在同一视图里区分更清楚。
- 下一步建议、复查、趋势和照护任务之间形成成员维度的统一摘要。

对研发的价值：

- 复用已有聚合结果，不引入新的查询链路。
- App 不需要自行理解长期管理内部规则。
- 后续如果补充成员维度的用药安全归属，可以在现有字段上扩展，不影响页面结构。
