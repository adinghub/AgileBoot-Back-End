# APP端药品近效期提醒设计

## 1. 目标

为个人药柜补充“药品近效期提醒”能力。

本次需求边界：

1. 仅提醒，不创建响铃通知
2. 提醒窗口固定为近效期 7 天
3. 提醒对象是库存批次，不是药品主档
4. 提醒结果进入 App 消息中心，并透传到首页消息预览

## 2. 为什么按批次提醒

同一药品可能同时存在多个库存批次，不同批次效期不同。

如果把“是否提醒过”挂在药品主档上，会导致：

1. 一个批次刚提醒完，另一个后续进入窗口的批次被误判为已提醒
2. 新补入的批次和旧批次之间相互覆盖提醒状态

因此本次把提醒状态放到 `drug_stock_batch`：

1. `near_expire_notified`
2. `near_expire_notify_time`

## 3. 触发规则

每日巡检所有仍有库存、且配置了效期的个人药品批次：

1. `stock_quantity > 0`
2. `expire_date != null`
3. `is_default_batch = 0`
4. `expire_date` 位于 `[今天, 今天 + 7天]`

命中后：

1. 若当前批次尚未提醒过，则创建一条 App 消息
2. 消息只进入站内消息中心，不调用设备 Push 发送器
3. 消息发送状态直接标记为成功，渠道写入 `IN_APP`

## 4. 去重与状态重置

同一批次在同一轮近效期窗口内只提醒一次。

当批次离开近效期窗口时：

1. `near_expire_notified` 重置为 `false`
2. `near_expire_notify_time` 清空

这样后续若因修正效期、重新入库等业务变化再次进入窗口，仍可重新提醒。

## 5. App 展示策略

本次不新增专门接口，直接复用现有消息中心 / 首页消息预览协议：

1. 新增消息场景 `NEAR_EXPIRY_ALERT`
2. 场景点击后跳转到工作台药品库对应药品详情
3. 归类到“提醒”消息分类中

## 6. 默认调度策略

新增药品近效期巡检任务：

1. 默认每天上午 9 点执行
2. 支持通过配置项覆盖 Cron
3. 检查天数默认 7 天，也允许通过配置覆盖

## 7. 本次不做的内容

1. 不发设备 Push
2. 不响铃
3. 不新增首页待跟进任务
4. 不做后台可配置提醒窗口页面
5. 不做消息详情专属页面
