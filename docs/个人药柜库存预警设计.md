# 个人药柜库存预警设计

> 说明：本设计文档记录的是个人药柜库存预警一期方案。  
> 2026-04-24 起，药品库存模型已扩展为“药品主档 + 批号效期库存明细”的一对多结构，请同时参考 [docs/个人药柜批号效期库存设计.md](/E:/code/health/healthtrail-back-end/docs/个人药柜批号效期库存设计.md)。

## 1. 功能目标

本次在现有“系统药品 + 个人药品 + 用药计划 + 用药提醒”能力上，补齐个人药柜库存闭环，支持以下核心场景：

1. App 用户可以手工新增自己的个人药品，并直接配置库存信息。
2. App 用户可以把系统药品“一键引入”到自己的个人药柜，形成可维护库存的个人条目。
3. 用户可以对个人药柜药品执行补库存操作。
4. 用户在提醒页标记“已服药”后，系统自动按本次剂量扣减库存。
5. 用户可以为每个个人药品单独设置库存预警值。
6. 当库存从安全区进入预警区间时，系统自动生成站内消息并走 App Push 提醒。


## 2. 设计原则

### 2.1 库存只挂在个人药柜条目，不挂在系统药品主数据上

原因如下：

1. 系统药品是全局共享数据，不能直接承载某个用户的个人库存。
2. 同一种系统药品，不同用户的库存、预警值、备注都应彼此隔离。
3. 用户“引入系统药品”后，本质上是在自己的药柜里创建一份个人副本，后续库存扣减都围绕这个副本进行。

### 2.2 自动扣减必须依赖统一库存单位

为了保证“服药后自动扣减库存”可计算，本次补充 `stock_unit` 字段，约定如下：

1. `stock_quantity` 和 `stock_alert_threshold` 的数值单位都以 `stock_unit` 为准。
2. 如果某条用药计划绑定的是启用了库存跟踪的个人药品，则该计划的 `dose_unit` 必须与药品的 `stock_unit` 一致。
3. 一期不做“盒 -> 片”这类复杂换算，只允许同单位自动扣减。


## 3. 核心业务模型

### 3.1 `health_drug` 扩展为“药品档案 + 个人药柜条目”

保留原有双层药品库模型，并新增以下字段：

1. `source_drug_id`：来源系统药品ID，仅“从系统药品引入到个人药柜”时使用。
2. `stock_quantity`：当前库存数量。
3. `stock_unit`：库存单位，例如 `片`、`粒`、`ml`。
4. `stock_alert_threshold`：自定义预警值。
5. `low_stock_notified`：当前库存预警周期内是否已经发送过提醒。
6. `low_stock_notify_time`：最近一次低库存提醒发送时间。

字段语义：

1. `owner_user_id = 0`：系统药品，不允许维护库存信息。
2. `owner_user_id = App用户ID`：个人药品或个人药柜条目，可维护库存。
3. `source_drug_id != null`：表示该个人药品由系统药品引入而来。
4. `source_drug_id = null`：表示该个人药品由用户手工新增。

### 3.2 新增库存流水表 `health_drug_stock_log`

该表用于沉淀库存变化审计轨迹，便于后续排查和扩展。

核心字段：

1. `log_id`
2. `owner_user_id`
3. `drug_id`
4. `change_type`
5. `before_quantity`
6. `change_quantity`
7. `after_quantity`
8. `stock_unit_snapshot`
9. `alert_threshold_snapshot`
10. `related_plan_id`
11. `related_reminder_id`
12. `operation_remark`

`change_type` 取值一期约定：

1. `IMPORT_INIT`：引入系统药品时初始化库存
2. `MANUAL_INCREASE`：手工补库存
3. `REMINDER_TAKE_DEDUCT`：标记已服药后自动扣减
4. `ALERT_THRESHOLD_UPDATE`：修改预警值


## 4. 关键业务规则

### 4.1 手工新增个人药品

用户手工新增个人药品时：

1. 仍沿用当前 `POST /app/drugs`。
2. 如果传了库存相关字段，则自动启用库存跟踪。
3. 如果填写了库存或预警值，则必须填写 `stockUnit`。
4. 如果只填写了预警值但没填写库存，则库存默认按 `0` 初始化。

### 4.2 引入系统药品

新增接口：`POST /app/drugs/{drugId}/import`

规则如下：

1. 仅允许导入系统药品。
2. 导入后的新数据落到 `owner_user_id = 当前用户ID` 的个人药品记录。
3. 药品基础档案字段默认复制系统药品数据。
4. `source_drug_id` 记录原系统药品ID。
5. 同一用户对同一系统药品只允许存在一条引入副本。
6. 导入时可同时指定初始库存、库存单位、预警值、备注。

### 4.3 手工补库存

新增接口：`POST /app/drugs/{drugId}/stock/increase`

规则如下：

1. 仅允许操作当前用户自己的个人药品。
2. 增加库存采用“增量变更”，不直接覆盖绝对值。
3. 如果药品之前尚未启用库存跟踪，则本次补库存可作为首次启用入口。
4. 当补库存后库存恢复到安全区，即 `stock_quantity > stock_alert_threshold` 时，自动清空 `low_stock_notified`，为下一轮预警重新打开开关。

### 4.4 修改预警值

新增接口：`PUT /app/drugs/{drugId}/stock/alert-threshold`

规则如下：

1. 仅允许操作当前用户自己的个人药品。
2. 允许传 `null` 关闭低库存提醒。
3. 如果设置新预警值后当前库存已经处于预警区间，且当前周期还未发送过提醒，则立即触发一次低库存提醒。

### 4.5 标记已服药后自动扣减库存

当提醒页调用 `POST /app/medication/reminders/{reminderId}/take` 时：

1. 先按原有逻辑把提醒状态改为“已服药”。
2. 再根据提醒所属计划读取计划绑定的 `drug_id`。
3. 只有当该药品是“当前用户自己的个人药品”且启用了库存跟踪时，才执行自动扣减。
4. 扣减数量直接取本次提醒对应的 `dose_amount`。
5. 计划 `dose_unit` 必须与药品 `stock_unit` 一致，否则计划创建/修改阶段直接拦截，不允许落库。
6. 如果库存不足本次剂量，不阻断“已服药”反馈，而是把库存直接扣到 `0`，并记录流水备注说明本次发生了“缺货归零”。

### 4.6 低库存提醒触发规则

提醒采用“进入预警区间触发一次”的策略，而不是每次扣减都触发：

1. 当 `stock_alert_threshold = null` 时，不做提醒。
2. 当 `stock_quantity <= stock_alert_threshold` 且 `low_stock_notified = false` 时，触发低库存消息。
3. 只有当设备 Push 真正发送成功后，才把 `low_stock_notified` 置为 `true`，表示当前低库存周期已经完成提醒。
4. 如果消息已创建但 Push 失败，则保留站内消息，同时保持当前周期仍可继续补发，不提前封口。
5. 只有在后续补库存把库存恢复到安全区后，才重新把 `low_stock_notified` 置回 `false`。
6. 如果用户后来重新登录并重新上报设备 Token，后端会补跑当前仍处于低库存状态、但尚未 Push 成功的药品提醒。


## 5. 消息提醒设计

### 5.1 消息场景

新增消息场景：

1. `LOW_STOCK_ALERT`

### 5.2 消息内容

建议文案：

1. 标题：`{药品名称} 库存不足`
2. 正文：`当前库存 {stockQuantity}{stockUnit}，已达到预警值 {threshold}{stockUnit}，建议尽快补充。`

### 5.3 跳转参数

新增页面编码：

1. `WORKSPACE_DRUG_CABINET`

点击消息后，前端可跳转到药柜列表页或指定药品详情页，优先引导用户执行“补库存”。

## 8. 一期边界

本次先做到：

1. 个人药品库存初始化
2. 系统药品引入个人药柜
3. 手工补库存
4. 服药自动扣减
5. 自定义阈值低库存提醒
6. 库存流水落库

本次暂不做：

1. 不同单位换算
2. 药品批次 / 有效期管理
3. 家庭共享库存协同编辑
4. 后台库存看板
5. 自动生成采购清单


## 9. 落地影响

### 9.1 对 App 前端

前端需要新增或调整以下能力：

1. 药品详情页补充库存卡片。
2. 系统药品列表支持“一键引入我的药柜”。
3. 个人药品编辑页支持库存单位、库存数量、预警值录入。
4. 提醒页无需改扣减逻辑，只需继续调用原“标记已服药”接口。
5. 消息中心增加 `LOW_STOCK_ALERT` 场景展示与跳转映射。

### 9.2 对测试

重点回归：

1. 手工新增个人药品并启用库存。
2. 系统药品导入后生成个人副本。
3. 补库存后库存数正确累加。
4. 服药后库存按剂量正确扣减。
5. 首次进入预警区间时只提醒一次。
6. 补库存恢复后再次跌破阈值时可重新提醒。
