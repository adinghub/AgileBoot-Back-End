# 后台消息批量重发接口对接文档

## 1. 说明

本文档用于后台管理端对接 App 消息批量重发接口。

当前接口定位：

1. 对勾选的多条消息统一补发
2. 返回整批汇总结果
3. 返回每条消息的执行明细


## 2. 接口地址

`POST /health/messages/batch-resend`


## 3. 请求参数

请求体示例：

```json
{
  "messageIds": [101, 102, 103]
}
```

字段说明：

1. `messageIds`：需要批量重发的消息ID列表

参数约束：

1. 不能为空
2. 单次最多 100 条


## 4. 成功响应示例

```json
{
  "code": 0,
  "msg": "操作成功",
  "data": {
    "requestCount": 3,
    "actualCount": 3,
    "successCount": 2,
    "failedCount": 1,
    "results": [
      {
        "messageId": 101,
        "success": true,
        "channel": "APP_PUSH",
        "message": "已派发到1个设备",
        "sendStatus": 1,
        "sendTime": "2026-04-23 16:00:00",
        "sendRetryCount": 2
      },
      {
        "messageId": 102,
        "success": false,
        "channel": "APP_PUSH",
        "message": "当前用户没有可用的活跃设备Token",
        "sendStatus": 2,
        "sendTime": "2026-04-23 16:00:01",
        "sendRetryCount": 3
      },
      {
        "messageId": 103,
        "success": true,
        "channel": "APP_PUSH",
        "message": "已派发到2个设备",
        "sendStatus": 1,
        "sendTime": "2026-04-23 16:00:02",
        "sendRetryCount": 1
      }
    ]
  }
}
```


## 5. 字段说明

### 5.1 顶部汇总字段

1. `requestCount`：请求中传入的消息数量
2. `actualCount`：去重后的实际执行数量
3. `successCount`：成功数量
4. `failedCount`：失败数量

### 5.2 单条结果字段

1. `messageId`：消息ID
2. `success`：本条是否成功
3. `channel`：本条执行通道
4. `message`：本条结果说明
5. `sendStatus`：消息表当前发送状态
6. `sendTime`：消息表当前发送时间
7. `sendRetryCount`：消息表当前发送重试次数


## 6. 后台对接建议

1. 建议列表页支持勾选多条失败消息后调用本接口
2. 接口返回后建议先展示顶部成功/失败统计
3. 再逐条回显 `results` 中的明细，方便用户知道哪些还需要继续处理
4. 如果 `actualCount` 小于 `requestCount`，说明本次请求里存在重复消息ID
