# 健康有迹家庭健康长期管理整体产品文档

## 1. 文档说明

本文档用于统一说明健康有迹当前家庭健康长期管理产品形态，覆盖 App 用户场景、核心能力、十项长期管理能力、数据闭环、版本边界和后续路线。

本文档面向三类角色：

1. 产品：用于确认产品定位、能力范围和后续优先级。
2. 研发：用于理解各模块之间的业务关系和实现边界。
3. 测试：用于梳理核心用户路径、验收范围和风险点。

## 2. 产品定位

健康有迹定位为面向个人和家庭的健康管理 App，重点不是替代医院系统，也不是提供医疗诊断结论，而是帮助用户把日常健康数据、检查报告、慢病专项、用药计划、家庭照护和就医资料持续沉淀起来。

产品核心价值可以概括为一句话：

> 让家庭健康数据有记录、有提醒、有解读、有行动、有沉淀。

当前产品以 App 为主要使用端，后台管理作为运营配置、消息管理、基础数据维护和风控支撑。

## 3. 目标用户

### 3.1 家庭健康管理者

典型用户是家里负责照顾老人、孩子或慢病成员的人。他们需要知道：

- 家庭成员最近有没有异常指标。
- 谁该复查了。
- 哪些药快没了或快过期了。
- 看医生前要准备哪些资料。
- 哪些照护事项还没有完成。

### 3.2 慢病长期管理用户

典型用户是高血压、糖尿病、高血脂、心血管风险、体重管理等需要长期记录和复查的人。他们需要：

- 记录血压、血糖、体重、心率、血氧等日常指标。
- 维护慢病专项档案和个人目标。
- 持续观察报告指标与目标范围的关系。
- 定期生成复查建议和就医资料。

### 3.3 子女与照护者

典型用户是为父母或家人远程管理健康的人。他们需要：

- 快速了解哪个成员最需要关注。
- 创建照护任务并跟踪完成情况。
- 获取可分享给医生或家属的资料摘要。
- 在不暴露过多隐私的前提下进行信息分享。

### 3.4 就医前临时整理用户

这类用户平时记录不多，但在看医生前希望快速整理资料。他们需要：

- 从家庭成员维度汇总报告、用药、慢病和健康问题。
- 快速生成资料包文本或长图内容。
- 区分完整资料和脱敏资料。

## 4. 产品目标

### 4.1 用户目标

1. 降低家庭健康管理的记忆成本。
2. 让长期健康数据能被持续使用，而不是只保存一次。
3. 把健康异常、复查、用药、照护转成明确行动。
4. 看医生前能快速准备结构化资料。
5. 在分享资料时能看见隐私边界。

### 4.2 业务目标

1. 形成高频记录场景：用药提醒、指标记录、健康任务。
2. 形成中频价值场景：报告解读、健康问题、复查建议。
3. 形成低频但高价值场景：就医资料包、家庭照护、长期管理摘要。
4. 为会员能力保留自然付费点，例如资料包导出、长期管理增强、报告深度解读等。

### 4.3 工程目标

1. 尽量复用已有主数据，避免每个能力重复建一套数据。
2. 由后端聚合长期管理结果，App 负责展示和动作承接。
3. 用统一门禁控制高级能力，避免页面各写各的会员判断。
4. 保持每个能力可以独立深化，同时能被长期管理统一汇总。

## 5. 产品范围

### 5.1 当前已覆盖范围

当前产品已经覆盖以下核心业务：

1. 家庭成员管理：成员资料、成员归属、共享查看基础能力。
2. 用药提醒：用药计划、提醒、服药记录、补录、跳过、撤销。
3. 药品与库存：个人药柜、批号效期、低库存和近效期提醒。
4. 检查报告：报告上传、解析、指标结果、异常建议、AI 摘要。
5. 健康问题：从报告和指标沉淀健康问题，支持状态流转与证据查看。
6. 慢病专项：病种配置、专项档案、个人目标、复查任务。
7. 首页任务：待跟进事项、推荐动作、任务详情和操作日志。
8. 健康洞察：工作台、健康时间线、就医资料包、健康问题中心。
9. 家庭健康长期管理：十项能力统一聚合和多期增强。
10. 会员门禁：高级能力按门禁点控制，支持后续策略调整。

### 5.2 当前不覆盖范围

当前产品明确不做以下事情：

1. 不提供医学诊断结论。
2. 不替代医生医嘱、药师建议或医院检查结论。
3. 不做医院 HIS、医保支付、处方流转等院内系统能力。
4. 不承诺自动发现所有健康风险。
5. 不把 AI 输出作为最终医疗判断，只作为健康资料整理和提示参考。

## 6. 核心业务闭环

健康有迹的核心闭环分为七步：

1. 建档：创建家庭成员，维护慢病专项和用药计划。
2. 记录：记录服药、日常指标、慢病日记和健康事件。
3. 解析：上传检查报告，形成指标结果、异常提示和健康问题。
4. 归因：把健康问题与慢病专项、报告证据、复查任务关联起来。
5. 行动：生成复查建议、照护任务、用药核对提醒和下一步建议。
6. 分享：生成就医资料包、长图内容和脱敏摘要。
7. 沉淀：通过健康时间线和长期管理视图持续回看家庭健康变化。

## 7. App 产品结构

### 7.1 首页

首页负责轻量提醒和快速行动，重点展示：

- 今日待办。
- 用药提醒。
- 待跟进任务。
- 健康摘要。
- 快捷进入关键模块。

### 7.2 健康洞察工作台

健康洞察工作台是健康数据的聚合页，重点展示：

- 复查闭环。
- 指标趋势预警。
- 就医资料包。
- 慢病日记。
- 照护看板。
- 用药安全。
- 周报月报。
- 语音录入。
- 健康时间线。
- 家庭长期管理。

### 7.3 家庭健康长期管理区

长期管理区是当前十项能力的主要承载区域，提供：

- 十项能力卡片。
- 今日指标和最近记录。
- 下一步建议。
- 成员关注摘要。
- 指标目标趋势。
- 用药规则。
- 复查建议。
- 照护任务。
- 资料包分享。
- 隐私摘要。

### 7.4 后台管理

后台管理承担配置、运营和审计支撑，重点包括：

- 慢病病种配置。
- 报告解析和报告管理。
- 消息中心和推送设备管理。
- 首页运营任务管理。
- 会员能力和门禁配置。
- 系统菜单和权限管理。

## 8. 家庭健康长期管理十项能力

### 8.1 能力总览

| 序号 | 能力 | 解决的问题 | 当前产品表现 | 主要数据来源 |
| --- | --- | --- | --- | --- |
| 1 | 家庭健康计划引擎 | 用户不知道家庭健康下一步该做什么 | 汇总慢病、复查、异常指标和健康问题，形成计划摘要 | 慢病专项、复查任务、健康问题、指标预警 |
| 2 | 日常指标记录 | 血压、血糖等日常数据散落难追踪 | 支持多类型指标记录，并生成近期趋势 | 慢病日记、日常指标记录 |
| 3 | 慢病随访模板 | 慢病管理容易只支持单一病种 | 复用病种配置，支持所有已维护慢病 | 慢病病种、专项档案、个人目标 |
| 4 | 复查任务规则 | 用户容易忘记复查或不知道复查原因 | 从慢病复查、健康问题和异常指标生成复查建议 | 复查任务、健康问题、报告指标 |
| 5 | 健康问题生命周期 | 报告异常缺少后续跟进 | 支持健康问题状态、证据链、复查提醒和慢病关联 | 健康问题、报告、报告指标、状态日志 |
| 6 | 就医资料包分享 | 看医生前整理资料成本高 | 生成资料包文本、长图内容和脱敏分享内容 | 家庭成员、报告、用药、慢病、健康问题 |
| 7 | 用药安全增强 | 用药计划缺少核对提示 | 提示重复用药、缺少剂量、缺少频次、过期仍启用等风险 | 用药计划、药品、库存批次 |
| 8 | 家庭照护协作 | 家属照护事项缺少闭环 | 支持新增、完成、取消照护任务，并形成分派摘要 | 首页运营任务、家庭成员 |
| 9 | 健康周报月报 | 用户缺少周期性健康回看 | 复用周报月报摘要，纳入长期管理能力卡片 | 健康洞察周期摘要 |
| 10 | 数据导出与隐私 | 用户不知道资料范围和分享风险 | 按类别展示可归档数据数量和隐私提示 | 成员、慢病、报告、用药、日记、问题、任务 |

### 8.2 当前完成状态

十项能力当前均已进入可用状态，并已经补齐多期增强：

1. 一期：建立长期管理聚合对象和十项能力卡片。
2. 二期：补充复查建议确认、照护任务完成/取消、隐私数据导出内容。
3. 三期：补充指标目标趋势、用药安全规则、照护分派摘要和资料包长图内容。
4. 四期：补充手动指标趋势和脱敏分享内容。
5. 五期：补充下一步建议，将复查、目标趋势、用药规则和照护任务统一排序。
6. 六期：补充成员关注摘要，按家庭成员聚合长期管理关注点。

## 9. 关键用户路径

### 9.1 家庭成员首次使用

1. 用户创建家庭成员。
2. 用户维护基础健康信息。
3. 用户添加慢病专项或用药计划。
4. 首页和健康洞察开始出现成员维度的数据。
5. 长期管理区显示该成员的计划、记录、问题和建议。

### 9.2 日常指标记录

1. 用户进入长期管理区。
2. 点击“记录指标”。
3. 选择成员和指标类型。
4. 填写数值、单位、记录时间和备注。
5. 保存后进入慢病日记和健康时间线。
6. 后续形成手动趋势和成员关注摘要。

### 9.3 报告上传到健康问题

1. 用户上传检查报告。
2. 系统解析报告基础信息和指标结果。
3. 异常指标生成提示。
4. 相关异常沉淀为健康问题。
5. 用户查看问题详情、证据链和状态历史。
6. 用户可把问题加入复查提醒。

### 9.4 慢病长期管理

1. 用户选择慢病模板或创建慢病专项。
2. 用户维护个人目标范围和随访建议。
3. 系统比对近期报告指标与目标范围。
4. 长期管理区展示目标趋势。
5. 有偏离或不可衡量时进入下一步建议和成员关注摘要。

### 9.5 家庭照护协作

1. 用户在长期管理区新增照护任务。
2. 选择成员、任务内容、风险等级和时间。
3. 任务进入照护中心和分派摘要。
4. 用户可完成或取消任务。
5. 操作结果影响长期管理摘要和成员关注摘要。

### 9.6 就医资料准备

1. 用户进入健康洞察或长期管理区。
2. 选择资料包分享、资料包长图或脱敏分享。
3. 系统汇总成员、慢病、报告、用药和健康问题。
4. 用户复制、系统分享或本地保存内容。
5. 用户可在隐私摘要中确认资料类别和数量。

## 10. 数据与聚合原则

### 10.1 主数据归属

长期管理不是新的主数据系统，而是聚合层。各类数据归属保持不变：

- 家庭成员仍归家庭成员模块维护。
- 用药计划和提醒仍归用药模块维护。
- 报告和指标仍归报告模块维护。
- 慢病专项和个人目标仍归慢病模块维护。
- 健康问题仍归健康问题模块维护。
- 照护任务当前复用首页任务体系。

### 10.2 聚合规则

1. 后端负责聚合、排序和业务判断。
2. App 只消费聚合结果和展示元数据。
3. App 不重新推导长期管理规则。
4. 周期性摘要和下一步建议优先复用已有数据。
5. 未确认的医学判断只展示为提示，不作为诊断结论。

### 10.3 性能原则

1. 首屏尽量使用一次聚合结果。
2. 成员关注摘要复用已计算数据，不重复读取明细。
3. 趋势类能力优先使用近期数据，避免全量历史拖慢页面。
4. App 不通过多个列表自行拼装长期管理首页。

## 11. 会员与高级能力

健康有迹已经具备会员等级、权益、门禁点和前后端统一校验能力。

当前适合会员化的能力包括：

1. 就医资料包导出和长图内容。
2. 高级报告解读。
3. 家庭长期管理增强能力。
4. 更多成员、更多慢病专项或更多周期摘要额度。
5. 数据归档和隐私导出增强。

会员限制的产品原则：

1. 基础健康数据不应轻易阻断用户查看。
2. 高级整理、导出、智能摘要和额度型能力适合纳入会员。
3. 会员失败提示要明确说明当前受限动作和升级价值。
4. 已埋点的门禁点后续应优先通过配置调整策略。

## 12. 运营与增长场景

### 12.1 高频留存

1. 今日用药提醒。
2. 日常指标记录。
3. 首页待跟进任务。
4. 低库存和近效期提醒。

### 12.2 中频价值

1. 报告上传与解读。
2. 健康问题跟进。
3. 慢病目标维护。
4. 复查建议确认。

### 12.3 高价值转化

1. 就医资料包。
2. 长期管理摘要。
3. 家庭成员关注。
4. 隐私导出和资料归档。
5. 周报月报和更深度的健康趋势分析。

## 13. 产品验收清单

### 13.1 长期管理总览

1. 能看到十项能力卡片。
2. 能看到今日指标、下一步建议、关注成员、最近记录、趋势、复查和照护任务数量。
3. 无数据时有明确空态文案。
4. 有数据时预览内容与详情弹窗一致。

### 13.2 日常指标

1. 支持血压、血糖、体重、心率、血氧、体温、症状、睡眠、运动和通用记录。
2. 保存后能进入最近记录。
3. 至少两条可量化记录后能形成趋势。
4. 趋势只作为观察提示，不写成医学结论。

### 13.3 复查与健康问题

1. 慢病复查、健康问题和异常指标能生成复查建议。
2. 复查建议可确认成任务。
3. 健康问题支持状态变更和历史查看。
4. 健康问题能关联或解除慢病专项。

### 13.4 照护协作

1. 能新增照护任务。
2. 能完成照护任务。
3. 能取消照护任务。
4. 分派摘要能展示成员和负责人信息。

### 13.5 就医资料与隐私

1. 能生成资料包文本。
2. 能生成长图内容文本。
3. 能生成脱敏分享文本。
4. 隐私摘要能展示资料类别和数量。

### 13.6 成员关注

1. 能按成员展示关注摘要。
2. 能展示复查、目标、照护、趋势等标签。
3. 有风险或行动更多的成员排在前面。
4. 平稳成员展示平稳观察标签。

## 14. 当前版本边界

当前版本已经具备完整的 1-10 能力闭环，但仍有一些明确边界：

1. 用药规则当前主要按计划维度生成，成员归属仍保留后续深化空间。
2. 周报月报当前偏规则化摘要，后续可加入更强的趋势分析和可读性优化。
3. 家庭照护当前复用任务体系，后续可扩展真实协作者角色、提醒和权限。
4. 慢病模板支持所有已维护病种，但病种配置质量决定用户体验上限。
5. AI 输出只作为辅助摘要，需要继续保留谨慎表达和兜底文案。

## 15. 后续路线

### 15.1 短期优化

1. 长期管理页视觉层级继续压缩，减少按钮过多带来的拥挤感。
2. 成员关注摘要增加成员头像、关系和最近记录时间。
3. 资料包长图从文本内容升级为 App 本地可渲染图片。
4. 隐私摘要增加更明确的分享前检查项。

### 15.2 中期增强

1. 用药安全规则按成员归属展示。
2. 周报月报加入成员维度和慢病维度摘要。
3. 家庭照护增加协作者角色、提醒、完成证据和任务模板。
4. 慢病专项增加病种级随访周期和指标目标模板。
5. 会员能力加入更多可配置套餐和额度展示。

### 15.3 长期方向

1. 做成家庭健康档案中心。
2. 做成慢病长期管理助手。
3. 做成就医前资料整理工具。
4. 做成家庭照护协同工具。
5. 在健康有迹基础上孵化更垂直的照护有迹或慢病有迹。

## 16. 核心指标

建议从以下指标观察产品效果：

1. 家庭成员创建率。
2. 用药计划创建率。
3. 日常指标记录频次。
4. 报告上传和解析成功率。
5. 健康问题查看率。
6. 复查建议确认率。
7. 照护任务完成率。
8. 资料包分享使用率。
9. 成员关注弹窗打开率。
10. 会员门禁触发后的升级转化率。

## 17. 一句话总结

健康有迹的家庭健康长期管理不是单个功能页，而是把家庭成员、慢病、报告、用药、问题、任务、资料和隐私统一组织成一个可长期使用的健康管理闭环。当前 1-10 能力已经形成基础完整形态，下一步应重点围绕体验压缩、成员维度深化、资料包可视化和会员价值表达继续增强。
