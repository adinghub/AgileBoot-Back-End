# 报告建议通知设计

## 1. 功能目标

当前系统已经具备：

1. 体检报告异常建议接口
2. 首页任务跳转参数
3. 推荐下一步动作
4. 统一 Push 业务透传载荷

但报告建议目前只存在于：

1. 报告详情页
2. 首页任务流

还没有接入通知入口。

因此本期补充“报告建议通知”能力，让用户在保存完异常报告结果后，可以收到一条可直接进入跟进页的通知。


## 2. 设计原则

### 2.1 与提醒通知使用同一套透传协议

报告建议通知直接复用：

1. `HealthAppPushPayloadDTO`
2. `navigation`
3. `recommendedAction`

这样客户端处理提醒通知和报告通知时，
可以共用同一套路由解析和推荐动作展示逻辑。

### 2.2 接入消息中心并做基础去重

本期在“保存报告指标结果”后：

1. 如果报告存在异常项
2. 先写入 App 消息中心
3. 再派发一条报告建议通知

同时会按“报告ID + 当前异常项签名”做基础去重。


## 3. 触发规则

### 3.1 触发时机

当前触发点：

`PUT /app/reports/{reportId}/items`

即保存报告结构化指标后。

### 3.2 触发条件

仅当报告存在异常项时触发：

1. 偏低
2. 偏高
3. 异常

若全部正常，则不派发通知。

### 3.3 去重规则

若同一用户对同一报告重复保存出相同异常集合，
则不重复创建消息、不重复推送。

当前异常集合签名会综合：

1. 指标名称
2. 异常标记
3. 结果值
4. 结果单位


## 4. 通知载荷

### 4.1 业务场景

报告建议通知使用：

`businessScene = REPORT_FOLLOW_UP`

### 4.2 跳转规则

统一返回：

1. `targetPageCode = HEALTH_REPORT_DETAIL`
2. `targetTabCode = ADVICE`

页面内锚点会按首条建议继续细分：

1. `REPORT_ADVICE`
2. `REPORT_ABNORMAL_ITEMS`
3. `REPORT_ORIGINAL_FILE`

### 4.3 推荐动作

推荐动作优先复用首条报告建议：

1. 标题取首条建议标题
2. 内容取首条建议内容
3. 动作文案取首条建议动作提示
4. 优先级取首条建议优先级
5. 风险等级按首条建议异常标记映射


## 5. 后续建议

建议下一步继续补：

1. 后台管理端通知审计页
2. 报告建议消息归档或删除能力
3. 多通道发送策略
