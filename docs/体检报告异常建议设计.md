# 体检报告异常建议设计

## 1. 功能目标

当前系统已经可以完成：

1. 体检报告上传
2. 结构化指标录入
3. 异常项识别
4. 报告摘要分析

但对于 App 用户来说，只看到“异常”还不够，还需要知道下一步应该做什么。

因此本期继续补充“报告异常建议”能力，目标是让报告详情页在异常摘要之后，继续输出可执行的业务建议。


## 2. 一期范围

### 2.1 当前实现

当前阶段已支持：

1. 基于异常项生成规则化建议
2. 针对重点指标生成专项建议
3. 联动当前成员是否已有启用中的用药计划
4. 输出报告级建议摘要与建议列表

### 2.2 暂未实现

当前阶段暂未实现：

1. 医学诊断结论
2. AI 个性化建议
3. 医院科室推荐
4. 线上问诊联动
5. 后台可配置规则引擎


## 3. 设计原则

### 3.1 只做业务建议，不做医学诊断

本期建议定位非常明确：

1. 告诉用户当前哪些异常项值得关注
2. 告诉用户可以做哪些后续动作
3. 告诉前端可以把用户引导到哪里

不会输出：

1. 疾病诊断
2. 治疗处方
3. 医学结论

### 3.2 建议必须可解释

每条建议都要能追溯到来源指标项，避免前端出现“只有建议，没有原因”的情况。

因此建议对象里会保留：

1. 来源指标ID
2. 来源指标名称
3. 来源指标结果值
4. 来源异常标记

### 3.3 建议优先联动现有业务能力

当前系统已经有用药计划和提醒能力，因此报告建议会优先复用现有业务：

1. 如果成员已经有启用中的用药计划，则提示查看现有提醒执行情况
2. 如果成员还没有计划，则提示可以补充健康管理安排


## 4. 规则设计

### 4.1 通用建议

每个异常项至少生成一条通用建议：

1. 偏高：建议复查确认
2. 偏低：建议关注变化
3. 异常：建议查看原始报告并结合医生意见确认

### 4.2 专项建议

当异常项名称命中特定关键词时，会继续追加专项建议。

当前一期支持：

1. 血糖类指标
2. 血脂类指标
3. 尿酸类指标
4. 肝功能类指标
5. 白细胞 / 中性粒细胞类指标

### 4.3 用药联动

对于血糖类等更适合持续管理的指标，如果成员已有启用中的用药计划，则建议直接引导查看现有用药提醒。

如果没有，则提示可补充健康管理安排。


## 5. 接口设计

App 端新增接口：

1. `GET /app/reports/{reportId}/advice`

返回内容包括：

1. 报告ID
2. 成员ID与成员名称
3. 异常项数量
4. 是否存在启用中的用药计划
5. 建议摘要
6. 建议列表


## 6. 后续建议

建议下一步继续补：

1. 后台可配置建议规则
2. 指标标准化映射
3. 报告异常项到健康看板任务的联动
4. 首页“待跟进事项”聚合
