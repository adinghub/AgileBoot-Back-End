# 健康洞察指标趋势预警增强设计说明

## 1. 背景

健康洞察工作台原有“指标异常趋势预警”只做了一层轻量判断：把近期报告里的异常指标按成员和指标分组，再按异常次数展示。这种方式能发现反复异常，但存在几个不足：

1. 没有先按报告日期确定最新值，最新报告和历史报告的展示顺序可能不够严谨。
2. 只能表达“出现过几次异常”，不能区分连续异常、单次最新异常和明显波动。
3. App 列表缺少波动方向、波动幅度、最新值等上下文，用户很难快速判断优先级。

本轮增强不新增持久化表，只在健康洞察工作台的运行时聚合里补齐规则结果。

## 2. 目标

本轮实现目标：

1. 按成员和指标聚合近期全部指标，而不是只聚合异常指标。
2. 按报告日期确定最新值和上一次值。
3. 支持连续异常、最新异常、明显波动三类规则。
4. 返回规则名称、连续异常次数、最新值、上次值、变化方向、波动百分比和原因标签。
5. 保留原有字段，避免旧版 App 因字段变化不可用。

本轮不做的内容：

1. 不新增预警表。
2. 不写入任务流。
3. 不生成医学诊断结论。
4. 不做病种级阈值配置，暂时使用统一轻量阈值。

## 3. 规则口径

### 3.1 分组口径

分组键由两部分组成：

1. 家庭成员 ID。
2. 指标编码，优先使用标准指标编码，其次使用原始指标编码，最后使用指标名称。

这样可以避免不同成员的同名指标混在一起，也能兼容报告指标暂时没有标准编码的情况。

### 3.2 最新值口径

同一分组内按报告日期倒序排列：

1. 第一条作为最新值。
2. 第二条作为上一次值。
3. 后续数据用于统计近期异常次数。

### 3.3 规则类型

| 规则类型 | 含义 | 风险层级 |
| --- | --- | --- |
| `CONTINUOUS_ABNORMAL` | 最新开始连续 2 次及以上异常 | 高 |
| `LATEST_ABNORMAL` | 最新报告该指标异常，但未形成连续异常 | 中或高 |
| `VOLATILITY` | 最新值相较上一次波动达到 20% 及以上 | 中 |

优先级：

1. 连续异常优先。
2. 最新异常其次。
3. 明显波动最后。

### 3.4 波动方向

| 方向 | 含义 |
| --- | --- |
| `UP` | 最新值高于上一次 |
| `DOWN` | 最新值低于上一次 |
| `UNCHANGED` | 最新值基本持平 |
| `NO_BASELINE` | 没有可比上一次数据 |
| `UNMEASURABLE` | 指标结果暂无法提取数值 |

## 4. 返回内容

预警项新增运行时字段：

| 字段 | 说明 |
| --- | --- |
| `latestReportDate` | 最新报告日期 |
| `previousReportId` | 上一次报告 ID |
| `previousReportDate` | 上一次报告日期 |
| `consecutiveAbnormalCount` | 从最新报告开始连续异常次数 |
| `latestResultValue` | 最新结果值 |
| `latestResultUnit` | 最新结果单位 |
| `previousResultValue` | 上一次结果值 |
| `previousResultUnit` | 上一次结果单位 |
| `changeDirection` | 变化方向编码 |
| `changeDirectionName` | 变化方向名称 |
| `changePercent` | 波动百分比 |
| `changeSummary` | 变化摘要 |
| `ruleType` | 命中的规则类型 |
| `ruleTypeName` | 命中的规则名称 |
| `alertReasons` | 原因标签列表 |

原字段继续保留：

1. `memberId`
2. `memberName`
3. `reportId`
4. `indicatorCode`
5. `indicatorName`
6. `abnormalFlagName`
7. `abnormalCount`
8. `riskLevel`
9. `alertTitle`
10. `alertContent`

## 5. App 展示

App 健康洞察工作台保持原卡片位置不变，只调整预警列表内容：

1. 标题仍显示“成员 + 指标需要关注”。
2. 副标题展示成员、规则原因、最新值和波动百分比。
3. 右侧短标签优先展示规则名称，例如“连续异常”“最新异常”“明显波动”。

这样用户在首屏就能看出：

1. 是哪位成员的问题。
2. 是连续异常还是单次异常。
3. 最新值是多少。
4. 是否出现明显波动。

## 6. 后续扩展

后续可继续增强：

1. 把 20% 波动阈值迁移到病种配置或指标模板配置。
2. 结合慢病个人目标范围，把“偏离个人目标”也作为预警规则。
3. 支持长期趋势规则，例如 3 次持续上升、长期未复查。
4. 对高风险预警生成待跟进任务，形成发现、提醒、处理、复查闭环。
