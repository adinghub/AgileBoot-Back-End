# 个人药柜批号效期库存设计

## 1. 功能目标

本次在既有“个人药柜库存预警”能力上继续深化，补齐以下能力：

1. 药品主档与库存批次明细彻底拆分，形成标准的一对多结构。
2. 用户在引入系统药品时，可以同时录入首批库存、批号和效期。
3. 用户后续补库存时，也必须按某个具体批次录入库存。
4. `batchNo` 可为空，但 `expireDate` 必填。
5. 药品库存展示按“批号 + 效期”维度展开，并按效期升序排序。
6. 标记已服药后，库存按最早效期优先扣减。


## 2. 核心模型

### 2.1 药品主档 `health_drug`

药品表只负责保存主档信息和库存配置，不再冗余保存库存总量。

保留的库存相关字段：

1. `stock_unit`：库存单位，例如 `片`、`粒`、`ml`
2. `stock_alert_threshold`：自定义库存预警值
3. `low_stock_notified`：当前预警周期内是否已经提醒过
4. `low_stock_notify_time`：最近一次低库存提醒时间

说明：

1. 药品总库存通过批次表实时汇总得出。
2. 这样可以避免“药品表汇总库存”和“批次表库存合计”双写后产生不一致。

### 2.2 批号效期库存表 `health_drug_stock_batch`

新增药品批次库存表，一条药品对应多条批次库存明细。

核心字段：

1. `batch_id`
2. `owner_user_id`
3. `drug_id`
4. `batch_no`：可为空
5. `expire_date`：效期，必填
6. `stock_quantity`

业务含义：

1. 同一药品可以有多个批次库存。
2. 同一药品下，相同 `batch_no + expire_date` 的补库存会合并到同一批次库存桶。
3. `batch_no = null` 也允许建库存批次，用于用户只知道效期、不方便录入批号的场景。


## 3. 关键业务规则

### 3.1 引入系统药品

接口：`POST /app/drugs/{drugId}/import`

规则：

1. 仅允许引入系统药品。
2. 导入后的药品主档仍落到 `health_drug`。
3. 如果本次录入了首批库存，则同时创建一条 `health_drug_stock_batch`。
4. 首批库存录入时，`expireDate` 必填，`batchNo` 可为空。
5. 返回结果中 `stockQuantity` 为实时汇总值，`stockBatches` 为批次明细列表。

### 3.2 新增个人药品

接口：`POST /app/drugs`

规则：

1. 用户可以手工新增个人药品。
2. 如果新增时同时填写首批库存，则也按照“药品主档 + 一条首批库存明细”的方式落库。
3. 如果只配置库存单位和预警值、不录入首批库存，则药品当前库存按 0 处理。

### 3.3 补库存

接口：`POST /app/drugs/{drugId}/stock/increase`

规则：

1. 每次补库存都必须指定本次库存对应的 `expireDate`。
2. `batchNo` 可为空。
3. 如果命中同一药品下的同一 `batchNo + expireDate`，则直接累加数量。
4. 如果没有命中，则新增一条批次库存明细。

### 3.4 库存展示

返回字段：

1. `stockQuantity`：由批次表实时汇总
2. `stockBatches`：按“效期升序 + 批号升序 + 批次ID升序”排序后的库存明细

展示规则：

1. 只展示当前库存数量大于 0 的批次。
2. 前端可直接按返回顺序展示，无需二次排序。

### 3.5 标记已服药后自动扣减

扣减规则：

1. 仅对当前用户自己的个人药品生效。
2. 仅对启用了库存跟踪的药品生效。
3. 扣减时按 FEFO 规则执行，即最早效期优先扣减。
4. 如果库存不足，不阻断“已服药”反馈，只扣减到 0。
5. 库存流水仍记录本次扣减前总量、变更量和扣减后总量。

### 3.6 低库存提醒

提醒规则不变，但当前库存由实时汇总得到：

1. 当 `stock_alert_threshold = null` 时，不提醒。
2. 当实时汇总库存 `stockQuantity <= stock_alert_threshold` 且当前周期未提醒过时，触发低库存提醒。
3. 当补库存后实时汇总库存重新高于阈值时，重置提醒周期。


## 4. 接口变更

### 4.1 请求字段

以下接口补充批次字段：

1. `POST /app/drugs`
2. `POST /app/drugs/{drugId}/import`
3. `POST /app/drugs/{drugId}/stock/increase`

新增字段：

1. `batchNo`
2. `expireDate`

### 4.2 返回字段

`DrugDTO` 继续保留：

1. `stockQuantity`
2. `stockUnit`
3. `stockAlertThreshold`
4. `stockTrackingEnabled`
5. `stockBelowAlert`

新增：

1. `stockBatches`


## 5. 数据库改动

### 5.1 `health_drug`

不再保存汇总库存字段：

1. `stock_quantity`

继续保留：

1. `stock_unit`
2. `stock_alert_threshold`
3. `low_stock_notified`
4. `low_stock_notify_time`

### 5.2 `health_drug_stock_batch`

新增整表与索引：

1. `idx_health_drug_stock_batch_owner_user_id`
2. `idx_health_drug_stock_batch_drug_id`
3. `idx_health_drug_stock_batch_expire_date`
4. `idx_health_drug_stock_batch_batch_no`


## 6. 设计收益

1. 药品主档和库存批次边界更清晰，后续扩展更稳定。
2. 不再需要维护冗余汇总库存，避免数据不一致。
3. 展示和扣减共用同一套批次排序规则，业务口径统一。
4. 后续如果增加“临期提醒”“批次盘点”“批次报损”等能力，可以直接在批次维度扩展。
